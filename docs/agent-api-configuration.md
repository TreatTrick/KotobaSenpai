# 使用外部 Agent 配置 API

在设置页的“让 AI 帮我配置 API”卡片中点击“复制配置提示词”，粘贴到本机 Codex、Claude Code 或 Cursor，补充服务商资料和 API Key 后发送。Agent 需要具备本机命令执行能力；官网或文档可以作为可选资料附上。提示词语言跟随软件当前选择的中文或英文。

提示词已包含当前安装目录的完整能力查询命令。Agent 首先执行 `capabilities --json`，按返回的输入格式调用工具；无需额外安装脚本运行环境、设置 PATH 或自己猜测 CLI 参数。

用户可以指定模型，也可以让 Agent 获取模型列表后自行选择便宜、快速且适合日语分析的文本模型。软件按 OpenAI Responses、Anthropic Messages、OpenAI Chat Completions 的顺序自动检测协议，复用正式识别的请求、解析和校验流程。

缺少 Key 或其他必要资料时，Agent 会提醒补充。只有官网时，Agent 需要查阅官方接入文档；无法读取时，请粘贴相关接入说明。API Key 继续保存在现有 JSON 设置文件中，提示词不会自动包含已经保存的密钥，工具结果也不会回显密钥。

中英文提示词均要求 Agent 在缺资料时逐行展示四项填写模板，明确提醒替换尖括号内容和 `YOUR_API_KEY`；官网或文档、模型偏好均可留空。已提供的资料无需重复填写，密钥不会回显。工具路径和接口版本由软件填写；若 Agent 提醒它们仍是占位符，请在软件中重新点击“复制配置提示词”，不需要自己查找路径或版本。

模型查询、只检测和状态查询保持界面运行。配置时，工具会先正常退出应用，再验证并保存，结束后恢复原先打开的界面；当前识别会中断。应用原本没有打开时，完成后也不会主动打开界面。退出超时会返回忙碌，不强杀应用。

CLI 与 UI 都是独立入口，直接调用同一个配置用例和基础设施实现。CLI 在自己的进程内完成模型查询、检测和保存，不启动 App 的配置子进程，也不初始化 WPF 界面、OCR 或词典；只有恢复原先打开的界面时才重新启动 App。设置文件继续由共用的 SettingsService 负责原子保存，两个入口通过同一进程互斥避免同时写入。

验证通过后才整体保存并启用，失败保留原配置。已保存但界面恢复失败时，请手动打开应用，不要因此重复配置；如果执行结果未确认，先让 Agent 查询状态。


高级手动配置默认展开并保留原有输入框。填写协议、地址、Key 和模型后，可以使用顶部左侧的“检测配置是否可用”，按当前协议执行真实日语分析检查。这个按钮只检查，不会自动切换协议、修改地址或应用配置；四项输入仍按原有方式即时保存。检测期间按钮内显示转圈等待动画并禁止重复点击，完成或取消后恢复。需要自动识别协议并填写配置时，使用上方的 Agent 配置入口。

云端 AI 分析是识别的必需流程，设置页没有启用或禁用开关。历史配置中的 `PhraseGroupsEnabled` 不再生效。配置缺失或服务请求失败时按现有错误状态提示补全或重试；不会切换为独立的本地分析模式。

发布软件时执行 `dotnet publish src/KotobaSenpai.App/KotobaSenpai.App.csproj -c Release -o artifacts/publish`。App 的构建和发布会自动将同版本 CLI 放入同一目录。分发时请保留完整发布目录，包括 CLI 的可执行文件、程序集与运行配置。

发布后可运行 `./tests/Check-AgentCli.ps1 -PublishDirectory ./artifacts/publish`，检查能力发现、输入校验、脱敏和帮助命令；该检查不会发送供应商请求或修改现有配置。

手动检测通过后，在检测按钮右侧显示绿色圆圈勾和“下方配置可以使用”，连接字段保持原样。Agent 配置成功后重开软件也会恢复此状态。软件保存与四项配置关联的验证指纹；修改协议、地址、密钥或模型后，旧提示清除，需要重新检测。该状态表示此配置曾通过验证，并不持续监测服务是否在线。

检测失败时，右侧显示红色三角感叹号和“配置不可用”，下方显示错误原因及技术详情，最右侧的“复制错误信息”按钮可复制脱敏后的详情。检测过程中修改配置会取消本次检测，避免过期结果覆盖新输入。软件不提供撤销配置功能，也不再生成历史配置记录。
