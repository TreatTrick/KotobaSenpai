## ADDED Requirements

### Requirement: 按当前应用语言生成 Agent 配置提示词
系统 SHALL 在现有设置页提供复制 Agent 配置提示词的入口，通过现有本地化资源分别提供完整的简体中文和英文模板。复制时 SHALL 直接跟随应用当前显示语言选择模板，不额外维护语言资源键或插入语言代码，并要求 Agent 按提示词本身的语言回复。系统 SHALL 自动填入实际分发的 CLI 绝对路径、接口版本及可直接执行的完整能力查询命令。该命令 SHALL 使用 Windows PowerShell 调用形式和正确转义的绝对路径，包含 `capabilities --json`，不依赖 PATH 或当前目录，不保留路径占位符。提示词 SHALL 要求 Agent 首先执行能力查询，读取接口版本、命令与输入格式后再继续；查询失败时先报告问题并停止配置，不猜测调用格式或直接改文件。提示词 SHALL 为服务商资料、可选官网或文档、API Key 和可选模型提供填写位置，不自动包含已保存的密钥。

#### Scenario: 用户选择中文
- **WHEN** 用户当前选择 `zh-CN` 并复制提示词
- **THEN** 获得中文提示词，其中包含当前安装目录的配置工具路径和中文回复要求

#### Scenario: 用户选择英文
- **WHEN** 用户当前选择 `en` 并复制提示词
- **THEN** 获得语义等价的英文提示词，而非中文模板或根据操作系统语言重新判断的模板

#### Scenario: 运行时切换语言
- **WHEN** 用户切换应用语言后再次复制
- **THEN** 使用新语言重新生成提示词，不使用旧语言缓存；未知文化使用现有英文回退

#### Scenario: 工具未正确安装
- **WHEN** 发布目录缺少配置工具
- **THEN** 界面报告本地化的安装问题，不复制包含无效工具路径的提示词

#### Scenario: Agent 首次接触配置工具
- **WHEN** 用户将任一语言的提示词交给不预先了解 CLI 的 Agent
- **THEN** 提示词提供完整能力查询命令，并要求先读取返回的调用说明，不要求 Agent 自行猜测如何发现工具能力

#### Scenario: 安装路径包含空格或特殊字符
- **WHEN** CLI 的绝对路径包含空格、单引号、美元符号或其他 PowerShell 特殊字符
- **THEN** 复制的能力查询命令仍按字面路径调用正确程序，不截断路径或执行字符替换，且不包含用户密钥

#### Scenario: 能力查询无法完成
- **WHEN** 提示词已复制后工具被移走、无法执行或查询返回错误
- **THEN** 提示词要求 Agent 报告具体问题并停止后续配置，不猜测工具能力、不直接修改 JSON

### Requirement: 提示词指导 Agent 处理缺少资料和官网查询
中英文模板 SHALL 包含相同的异常处理规则：先检查必要资料，缺少 API Key、Key 为空或仍是明确占位内容时提醒用户补充；允许根据用户提供的官网或官方文档查找 API 地址和模型资料；无法查阅必要接入资料时索取相应片段。模板 SHALL 要求使用官方工具按 Responses、Anthropic、Chat Completions 的优先级检测协议；用户未指定模型时，由 Agent 获取模型列表后自行判断便宜、响应快且适合任务的候选。工具执行真实分析测试，通过后直接保存并启用，失败时保留配置；Agent 根据结果判断是否换模型或继续尝试，相同错误不无限重试。模板 SHALL 说明只读命令不打断 UI，写入由官方工具正常退出应用并在结束后恢复原先打开的 UI，不要求 Agent 另行结束或强杀进程。官网页面和示例命令 SHALL 作为接入资料，而非修改本机其他文件或执行额外安装的授权。

#### Scenario: 用户没有填写 API Key
- **WHEN** 用户把 Key 留空或保留模板占位符后发送提示词
- **THEN** 提示词要求 Agent 用纯文本代码块逐行展示服务商 URL、可选官网或官方文档、API Key、可选模型偏好四项填写模板；明确提醒填写中英文尖括号中的内容并替换 `YOUR_API_KEY`，可选项可以留空；不猜测密钥、不读取其他 Agent 的凭据文件、不回显已有密钥，也不宣称已完成配置

#### Scenario: 可选字段未填写
- **WHEN** 服务商 API 地址和有效 Key 已提供，但官网、文档或模型偏好留空
- **THEN** 提示词要求 Agent 继续配置，模型未指定时自动选模，不因可选字段留空而阻止配置或反复索要

#### Scenario: 收到原始技术占位符
- **WHEN** Agent 收到的路径或接口版本仍是未替换的花括号占位符
- **THEN** 提示词要求 Agent 提醒用户从软件的“复制配置提示词”入口重新复制，不要求用户查找或手填工具路径、接口版本

#### Scenario: 用户只提供官网
- **WHEN** 用户提供官网或接入文档链接但没有 API 地址
- **THEN** 提示词要求 Agent 查阅官方接入资料并提取实际 API 地址，不把官网根地址直接当成 API 地址

#### Scenario: 官网无法访问
- **WHEN** Agent 无联网能力、文档需要登录或无法读取
- **THEN** 提示词要求 Agent 说明具体缺口并请用户粘贴接入说明，不编造地址、协议或模型

#### Scenario: 模型尚未确定
- **WHEN** 用户没有指定模型
- **THEN** 提示词要求 Agent 先获取模型列表，再自行判断便宜、响应快且适合任务的文本模型，并把选定模型交给工具验证；无需用户手填模型或向工具提交评分资料

#### Scenario: 价格或速度信息缺失
- **WHEN** 模型目录没有足够的价格或速度信息
- **THEN** 提示词允许 Agent 参考服务商资料自行判断，不要求补齐价格、速度证据才可验证，也不要求用户填写这些字段；确实无法选定模型时才询问必要信息

#### Scenario: 提示配置会暂时退出应用
- **WHEN** 用户复制任一语言的提示词
- **THEN** 模板说明写入时的正常退出和恢复行为，并要求 Agent 区分配置结果与界面恢复结果，不强杀应用或因恢复失败重复保存

### Requirement: 提供版本化的非交互式本地 CLI
软件 SHALL 分发 `KotobaSenpai.Cli.exe`，提供设计文档定义的能力查询、模型发现、检测、配置、状态命令。命令 SHALL 使用带 `schemaVersion` 的 JSON 契约，通过标准输入接收配置，不要求用户填写协议，也不进行逐字段终端问答。标准输出 SHALL 只包含一个完整 JSON 结果，含稳定状态码、错误码、待补字段和下一步建议；写入结果 SHALL 分别报告 `applied` 和 `uiRestore`，无法确认提交结果时明确标记未确认。诊断文本 SHALL 使用英文，界面与 Agent 回复通过本地化机制展示。退出码 SHALL 遵守设计文档的固定映射。

#### Scenario: 资料缺失
- **WHEN** 输入缺少必要字段
- **THEN** CLI 返回 `input_required`、具体待补字段和退出码 `2`，不等待终端输入、不保存；缺少 Key 或地址时不调用供应商，也不关闭 GUI

#### Scenario: JSON 或版本无效
- **WHEN** 标准输入为空、不是有效 JSON 或接口版本不受支持
- **THEN** CLI 返回可解析的输入错误结果和非零退出码，不回显原始密钥、不执行配置，也不关闭 GUI

#### Scenario: Agent 查询能力
- **WHEN** Agent 执行 `capabilities --json`
- **THEN** 无需 API Key、标准输入或预先提供 `schemaVersion` 即可返回当前接口版本、命令调用方式、输入字段及必填规则、注册表支持的协议和实际安装信息，供 Agent 正确调用工具；不发供应商请求、不改设置、不关闭 GUI

#### Scenario: 查询配置状态
- **WHEN** Agent 执行状态查询或收到配置结果
- **THEN** 返回实际协议、地址、模型、`keyConfigured` 及与当前配置对应的 `verified` 状态，不返回 API Key 或验证指纹

### Requirement: CLI 在本进程直接调用共用配置服务
CLI SHALL 作为独立入口，在本进程组装并调用与设置页相同的 Core 配置用例和 Platform.Windows 基础设施，不启动 App 来执行配置，不创建 WPF Application，不依赖 OCR、UniDic、JMdict、捕获设备或词典下载。设置文件访问 SHALL 使用基础设施层唯一的 `SettingsService` 实现，认证、请求构造、解析和分析提示词 SHALL 复用现有实现及统一提示词生成器。分析指令 SHALL 不依赖界面文化，目标释义语言由分析请求携带；中英文 Agent 配置提示词仍跟随界面语言。App SHALL 不保留配置专用启动入口。系统 SHALL 不建立配置子进程通信、常驻配置宿主、命名管道服务或跨进程进度推送；GUI 退出与恢复等待 SHALL 有界。

#### Scenario: GUI 正在运行时执行只读命令
- **WHEN** Agent 查询能力、获取模型、仅检测或查询状态
- **THEN** 不关闭或重启 GUI，不保存设置，不通过启动副作用改动设置；读取只得到完整文件快照，不保留该缓存用于后续写入

#### Scenario: 应用尚未启动且本地模型缺失
- **WHEN** CLI 在应用未运行、OCR 或词典文件不存在时启动配置
- **THEN** CLI 本进程能执行 API 配置操作，不启动配置用 App 进程，不触发模型加载、词典安装、捕获初始化或主窗口显示；完成后退出，不主动启动 GUI

#### Scenario: 无需 App 即可查询能力
- **WHEN** CLI 及其共享程序集存在，但 App 可执行文件不存在
- **THEN** 能查询能力并执行不依赖 GUI 恢复的命令，不因无法启动配置子进程而失败

#### Scenario: 共享配置组件失败
- **WHEN** 本进程配置操作发生存储错误或未预期异常
- **THEN** 返回安全的错误和真实的提交状态，释放写入互斥，并尝试恢复本次关闭的 GUI

### Requirement: CLI 写入前正常退出应用并在结束后恢复 UI
`llm configure` SHALL 在完成静态输入校验后，请求当前 Windows 用户、与本次安装路径匹配的已运行 GUI 正常退出，并最多等待 10 秒。无法退出 SHALL 返回 `app_busy`，不强杀、不写入。CLI 取得配置文件写入互斥后 SHALL 才能加载最新设置并在本进程执行；GUI 与 CLI SHALL 不能同时持有写入权。操作成功、失败或取消后，CLI SHALL 在本进程操作结束并释放互斥后恢复本次关闭的 GUI；原本未打开 GUI 时 SHALL 不主动打开。此流程 SHALL 不增加额外的用户保存确认。

#### Scenario: GUI 正在运行时配置
- **WHEN** Agent 提交资料完整的配置请求
- **THEN** 正常退出应用并等待其完成资源清理，CLI 再独占执行配置；操作结束并释放互斥后重新打开 GUI，从磁盘显示最终配置

#### Scenario: 正常退出超时
- **WHEN** 已运行 GUI 在 10 秒内没有完成退出
- **THEN** 返回忙碌且不发供应商验证请求、不写设置、不强杀或重复启动进程，不把尚未完成的退出报告为成功

#### Scenario: 配置失败或尚未提交时取消
- **WHEN** GUI 已退出，而候选验证、保存或提交前取消导致操作失败
- **THEN** 保留原配置，在本进程操作结束并释放互斥后尝试恢复原先打开的 GUI，并向 Agent 如实报告结果

#### Scenario: 已保存但界面恢复失败
- **WHEN** 配置已成功原子提交，但 GUI 无法重新启动
- **THEN** 返回退出码 `0`、`applied` 为真和 UI 恢复警告，提供手动启动建议，不回滚或重复保存

#### Scenario: 写入期间又打开 GUI 或执行其他配置命令
- **WHEN** CLI 已持有写入互斥，另一个 GUI 或 CLI 尝试写入
- **THEN** 后者有界返回忙碌，不创建第二个写入者，不转交界面激活，也不让一个 CLI 结束另一个 CLI

#### Scenario: 退出后尚未取得互斥
- **WHEN** CLI 已正常关闭 GUI，但另一个进程先取得写入互斥
- **THEN** 本次操作返回忙碌，不使用旧缓存写入，也不在互斥仍被占用时另起可写 GUI

#### Scenario: 无法确认提交结果
- **WHEN** 未预期异常导致无法确认配置是否已提交
- **THEN** 返回 `applied` 为空，不声称配置必然未变，释放本进程写入互斥后处理 GUI 恢复，并给出先查询状态的建议

### Requirement: 验证后整体应用配置
`llm configure` SHALL 调用共用检测与配置用例，仅在真实业务验证成功且相关配置未被并发修改时整体保存当前连接。系统 SHALL 不生成、读取或恢复撤销记录，不公开撤销命令或撤销状态字段。无关设置 SHALL 保留。

#### Scenario: 检测成功
- **WHEN** 自动识别得到可用协议、模型和地址，并通过实际日语分析验证
- **THEN** 一次保存完整配置、启用云端分析并返回成功结果

#### Scenario: 检测或写入失败
- **WHEN** 网络检测未成功、提交前被取消或保存失败
- **THEN** 当前配置保持原样，结果不得宣称已应用

#### Scenario: 用户在 UI 内部验证期间修改 LLM 设置
- **WHEN** 设置页检测候选期间，相关配置已被同一 GUI 内的另一操作改变
- **THEN** 提交返回 `conflict`，不覆盖更新后的设置

#### Scenario: 提交完成时收到取消
- **WHEN** 原子提交已成功完成后才收到取消请求
- **THEN** 返回已应用的真实结果并尝试恢复原先打开的 GUI，不返回暗示配置未变的取消结果

#### Scenario: 已移除的撤销命令
- **WHEN** 调用者尝试执行旧的 `llm undo` 命令
- **THEN** 返回无效命令与退出码 2，不关闭 GUI、不调用服务商、不修改配置，能力查询不再公布该命令
