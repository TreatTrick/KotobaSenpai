## Why

购买了 API 服务的用户未必理解接口地址、协议和模型配置。用户应能把服务商资料和密钥交给外部 Agent，由 KotobaSenpai 自动识别协议、验证实际分析能力并完成配置，无需逐项填写技术参数。

## What Changes

- 在现有设置页增加 Fluent 风格的“让 AI 帮我配置”卡片，按用户当前选择的语言复制简体中文或英文提示词。自动填入本机配置工具路径和可直接执行的 `capabilities --json` 完整命令，要求 Agent 先查询能力再按返回的命令与输入格式操作；允许附加服务商官网或文档，并覆盖缺少密钥、模型不明确、官网无法访问、服务不支持和请求失败等边界情况。
- 随安装包提供本地 Windows CLI，以带版本号的 JSON 输入输出公开能力查询、模型发现、自动检测、验证配置、状态查询。缺少资料时返回明确的待补字段，由 Agent 提醒用户补充，不要求用户操作交互式终端。
- CLI 默认按 OpenAI Responses、Anthropic Messages、OpenAI Chat Completions 的优先级自动识别可用协议，通过有界的真实请求确认，不要求用户手填协议；官网资料用于补齐候选地址，不把后序协议提前。
- 用户未指定模型时，由外部 Agent 获取服务实际返回的模型列表，自行判断并选择便宜、响应快且适合任务的文本模型，再交给工具验证。软件负责模型发现与真实分析验证，不内置价格、速度排序或选择证据契约。
- CLI 和 UI 共用配置用例，以及现有识别流程的协议注册、认证、地址候选、请求构造、HTTP 执行、解析和语义校验，不另写一套供应商客户端。
- 云端 AI 分析为识别的必需流程，移除设置开关及运行时禁用分支。连接快照只包含协议、地址、Key 和模型，历史启用键和旧撤销记录中的启用字段不再影响执行。
- CLI 写入配置时，先让已运行的应用正常退出，再取得互斥，在 CLI 本进程直接调用共用服务；操作结束并释放互斥后恢复原先打开的 UI。候选先验证、成功后整体保存并启用，失败保留原配置，保留无关设置。只读命令不关闭 UI。
- 按用户要求，密钥继续使用现有 JSON 设置文件中的 `LlmApiKey` 保存，不引入 DPAPI、凭据库或新的密钥录入流程。生成提示词不自动包含已保存的密钥，命令结果和日志继续脱敏。

## Capabilities

### New Capabilities

- `agent-api-configuration`：中英文配置提示词、面向外部 Agent 的本地 CLI、应用进程协作、边界反馈、验证后应用。
- `llm-connection-autodetection`：CLI 与 UI 共用的模型发现、有界协议识别及选定模型的真实日语分析验证，检测期间不修改当前配置；模型取舍由外部 Agent 判断。

### Modified Capabilities

- `llm-settings`：增加 AI 配置入口、共用的自动检测操作、配置进度与应用暂时退出的说明；CLI 配置后重新打开界面读取最终值，保留高级手动配置与现有 JSON 键。
- `llm-protocol-abstraction`：要求 UI、CLI、验证和正式识别复用同一套协议与请求执行实现，支持显式传入候选配置快照。
- `llm-phrase-groups`：云端分析作为识别服务必需依赖，不再提供禁用后的独立本地模式，保留等待和失败时的读音预览与错误状态。
- `settings`：将唯一设置文件实现放到基础设施层，增加字符串键值的原子批量读写和写入失败保护，以进程互斥保证 GUI 与 CLI 写入不重叠。

## Impact

- Core：配置契约、应用用例及领域类型无关的设置批量读写契约；保持无 WPF、文件系统和 HTTP 依赖。
- Platform.Windows：共用设置持久化、分析提示词资源、HTTP 策略、协议注册、地址处理、模型目录、分析器及 GUI 生命周期适配。
- App：UI 本地化资源、LLM 设置 ViewModel、Fluent 设置卡片和普通 GUI 组合根，不承担 CLI 配置执行宿主职责。
- 新增随软件分发的控制台入口；直接在本进程组装共用配置服务和基础设施，不启动 App 执行配置，不复制文件读写或供应商请求实现。
- 测试覆盖协议识别与请求复用、缺少资料、中英文切换、真实响应校验、原子保存与并发、正常退出与恢复 UI、打包和最终配置显示。
- 本次不包含 MCP 服务、常驻配置宿主、命名管道服务、跨进程配置热更新、云端解析服务、新增供应商协议、修改外部 Agent 自身配置或密钥加密迁移。
