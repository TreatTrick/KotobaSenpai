## Context

当前仓库的 Demo 已验证 LibNMeCab 可以在本地产出日语词面、读音、词性和字符偏移，但没有 Windows UI、窗口捕获或屏幕坐标模型。第一阶段必须在 Windows 10/11 上完成一个可运行的闭环，同时保持计划中 Core 不依赖 WPF/Win32 的边界。参考 modular-monolith-with-ddd 的做法，领域对象负责不变量，平台模块通过端口适配外部能力，应用层编排用例。

## Goals / Non-Goals

**Goals:**

- 建立 `WindowSelection`、`OcrWord`、`ScreenRect` 和 `WordOverlaySession` 等领域对象，保护句柄、矩形和词范围不变量。
- 通过 Win32 枚举可见顶层窗口并保存选择结果；通过 Windows Graphics Capture 获取单帧。
- 通过 Windows.Media.Ocr 使用日语 OCR，保留 OCR 词级坐标。
- 将捕获客户区坐标结合窗口边界和 DPI 转为屏幕像素坐标。
- 在一个透明置顶 WPF 窗口中绘制每个词的细线下划线，并支持刷新/隐藏。
- 为纯领域逻辑和坐标变换提供不依赖真实桌面状态的自动化测试。

**Non-Goals:**

- 不实现 LLM、词义解释、振假名、缓存、账号或截图上传。
- 不支持独占全屏注入；捕获失败时只显示可操作错误。
- 不把原始截图或窗口标题持久化到磁盘。

## Decisions

1. **按 DDD 分层，而不是让 WPF 直接调用 Win32。** `VnLearning.Core` 定义值对象、聚合和端口；`VnLearning.Platform.Windows` 实现窗口枚举、捕获、OCR 和坐标；`VnLearning.App` 只依赖 Core 端口并负责 ViewModel。这样窗口句柄和图形 API 不会污染领域模型，也便于未来增加其他平台。

2. **采用按需单帧捕获。** 用户点击“识别当前窗口”时才捕获一帧并运行 OCR，避免连续录屏和不必要的隐私/性能成本。捕获实现隔离在 Windows 适配器中；当前阶段使用 GDI 屏幕帧以兼容所有 WPF 桌面窗口，后续可在同一端口替换为 Windows.Graphics.Capture，不改变领域或 UI 契约。

3. **坐标以屏幕物理像素表示。** OCR 返回的词框以捕获帧像素为基准，`CoordinateTransformer` 将其按捕获帧与窗口屏幕矩形的比例映射。WPF 覆盖层使用系统 DPI 感知并把物理像素转换为 DIP，测试覆盖 100%、125% 和 150% 缩放。

4. **覆盖层使用独立透明窗口。** 覆盖层无边框、置顶、透明且默认点击穿透；下划线由 `UnderlineGeometry` 生成，词框宽度不足时至少保留 1px 线宽。覆盖层只接收当前会话的不可变词列表，刷新采用整体替换以避免残留线条。

5. **OCR 与分词职责分离。** 本阶段 OCR 词本身作为可视化单元；若系统 OCR 只返回行文本或语言包缺失，则会话失败并给出安装日语 OCR 语言包的提示，不用模型猜测坐标。

## Risks / Trade-offs

- [Windows 日语 OCR 语言包缺失] → 启动识别前检查 `Windows.Media.Ocr` 可用性，返回安装说明并允许重试。
- [DPI/多显示器导致下划线偏移] → 统一使用物理像素领域值对象，显式读取窗口 DPI，加入比例和边界测试。
- [独占全屏无法被 Graphics Capture 捕获] → 在 UI 中提示改用窗口化/无边框模式，本阶段不做进程注入。
- [透明窗口抢焦点或挡住游戏输入] → 覆盖层设置无激活、点击穿透和工具窗口样式；仅在后续交互需求出现时切换可交互模式。
- [OCR 词框跨行或空文本] → 过滤空框，逐词绘制；跨行词按 OCR 返回的多个框分别绘制，并在 Core 中拒绝负宽高矩形。

## Migration Plan

1. 新增三个项目和解决方案入口，保留现有 Demo。
2. 首次启动枚举窗口；用户选择后仅在进程内保留句柄。
3. 捕获、OCR、坐标转换和覆盖层均为一次性会话；关闭应用即清理内存状态。
4. 回滚时移除新增项目引用即可，不涉及数据库或配置迁移。

## Open Questions

- 不同游戏的文字区域是否需要在下一阶段加入手动框选；本阶段先覆盖整个客户区。
- 日语 OCR 的语言包安装是否需要集成跳转链接；本阶段提供错误文本和系统设置 URI。
