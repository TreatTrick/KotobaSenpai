## 背景

KotobaSenpai 是一个 Windows WPF 应用，拥有 Core 设置端口和由 App 管理的 JSON 设置实现。Windows 平台已经包含三种短语分析 wire 协议，分析器也会读取 `LlmApiKey`、`LlmEndpoint` 和 `LlmModel`，但协议解析目前只在依赖注入初始化时执行一次。主窗口没有暴露任何 LLM 配置字段，也没有组件知道如何列出模型。

本次变更必须继续使用单一供应商配置。它需要适配现有的 `ISettingsService` 字符串键契约，保留本地短语分析回退，继续允许手动输入模型，并且不引入数据库或新的 UI 框架。本迭代按照产品要求，继续把 API Key 作为现有普通字符串设置保存。

## 目标 / 非目标

**目标：**

- 提供本地化的 WPF 配置界面，用于启用短语分析、选择协议、输入端点和 API Key、发现模型并选择模型。
- 继续使用现有扁平设置键保存当前配置，并通过 `ISettingsService` 立即持久化每个字段。
- 在每次请求开始时根据当前设置解析协议及其认证行为，使修改无需重启应用即可生效。
- 使用有时间上限且可取消的 HTTP 请求获取模型目录，支持协议专属认证以及常见目录响应格式的宽松解析。
- 支持以 `/v1`、`/v4` 或常见兼容后缀结尾的 Base URL 候选地址，并在模型发现失败时保留手动输入模型的能力。
- 保持现有分析器契约；当配置不完整或供应商调用失败时，保留本地短语分析的回退结果。

**非目标：**

- 多个已保存供应商、供应商 Profile、故障转移队列、聚合、路由或账户/OAuth 流程。
- 自动供应商预设或远程供应商目录。
- 修改语义短语 prompt、响应 schema、OCR 流程、悬浮层行为或短语结果缓存。
- 在本次变更中加密 Secret 或迁移到 Credential Manager；明文设置存储是本版本明确的产品决策。

## 决策

### 1. 在 `ISettingsService` 中保留一个当前配置

UI 读取和写入 `PhraseGroupsEnabled`、`LlmProtocol`、`LlmEndpoint`、`LlmApiKey` 和 `LlmModel`。现有键保持兼容，缺失值继续表示未启用或未配置。每个字段都立即写入，这与当前设置服务的行为一致。

另一种方案是在 SQLite 或嵌套 JSON 中引入供应商集合。它可以支持未来的多供应商切换，但会增加迁移和编辑复杂度，且不能解决当前首次配置问题。扁平的单一配置已经足够，并且为以后迁移留下清晰路径。

### 2. 通过注册表在请求时解析协议

新增一个小型 `LlmProtocolRegistry`，将持久化值 `openai-chat`、`openai-responses` 和 `anthropic` 映射到协议描述符。描述符负责协议实现、请求路径、prompt 配置和认证策略。`LlmPhraseAnalyzer` 在读取设置后向注册表请求当前描述符，而不是接收一个固定的 `ILlmProtocol` 单例。

缺失或未知键时仍默认使用 OpenAI Chat Completions。这既保持现有行为，也让 UI 可以恢复无效设置。

### 3. 让认证按协议处理

扩展协议端口，增加应用请求头的方法。OpenAI 协议使用 `Authorization: Bearer <key>`。Anthropic Messages 使用 `x-api-key: <key>` 和 `anthropic-version: 2023-06-01`，不发送 Bearer 请求头。模型发现也使用同一认证策略。

相比在传输层按协议名称分支，这种做法更合适，因为wire 适配器本来就拥有供应商特有的细节。它也让测试能够直接断言各协议的请求头。

### 4. 增加专用模型目录端口和适配器

引入 `ILlmModelCatalog`，其可取消方法接收 endpoint、API key 和 protocol。Windows 实现按以下顺序构造候选 URL：

1. 如果以后由 UI 或描述符暴露显式模型 URL，先尝试规范化后的显式 URL。
2. 当 Base URL 以 `/v1` 或其他数字版本段结尾时，使用 `{base}/models`。
3. 对普通 Base URL 使用 `{base}/v1/models`。
4. 移除 `/anthropic`、`/api/anthropic`、`/claudecode` 或 `/api/coding` 等已知兼容后缀后，再尝试根路径回退地址。

每个候选地址都使用较短的超时。404 和 405 继续尝试下一个候选；认证失败、传输失败和成功但格式错误的响应都会转换为供本地化 UI 映射的类型化失败。成功响应支持 `data[].id`、可选的 `data[].owned_by`，以及作为回退的 `models[].slug`/`models[].id`。ID 会被去除空白、去重并排序。

模型目录与短语分析分离，因为模型发现有不同的响应格式、回退规则和 UI 生命周期。另一种方案是向 `ILlmProtocol` 增加发现方法，但那会让短语响应协议负责另一个目录资源，并使现有测试面变得复杂。

### 5. 保持模型选择可编辑

模型控件是一个可编辑的 `ComboBox`，绑定到持久化的模型字符串。成功获取后替换内存中的列表，并允许用户选择其中一项；用户仍可输入返回列表之外的模型 ID。获取结果只在当前会话有效，不会作为第二份目录持久化。

模型列表通过单个“获取模型”按钮显式获取，再次点击同一按钮即可刷新已有列表。这样可以避免用户输入过程中发送 API Key，也让网络活动更可预期。

### 6. 将配置 UI 放在专用 ViewModel 中

在 `App.ViewModels` 下增加 `LlmSettingsViewModel`，包含可观察属性、统一的获取模型命令、`IsFetchingModels` 和本地化状态/错误属性。同一命令支持首次获取和后续刷新。它依赖 `ISettingsService`、`ILlmModelCatalog` 和 `IStringLocalizer` 端口。主窗口通过组合根提供的属性绑定到该 ViewModel。

ViewModel 负责检查缺少 endpoint/key 的本地前置条件，立即持久化有效编辑，取消被新的获取操作替代的请求，并且绝不在状态文本中暴露 API Key。错误分类基于类型化的目录失败，而不是原始供应商响应体。

### 7. 在分析器中规范化 endpoint 拼接

分析器会规范化配置的 Base URL 和协议路径，避免重复版本段和尾部斜杠错误。Base URL 可以是主机根路径、带版本的 Base URL 或兼容子路径。规范化器不会悄悄改写任意用户路径；候选地址生成和分析器请求构造共用一个带测试的小型 URL 帮助器。

## 风险 / 权衡

- [API Key 明文存储] → 按要求，本版本将 key 存入 `settings.json`；日志、诊断信息和面向用户的错误仍必须脱敏。之后可以迁移到 Secret 存储。
- [供应商特有的 `/models` 行为] → 使用有序候选地址、有界超时、宽松响应解析，并在发现不可用时保留手动输入模型。
- [协议不匹配] → 协议选择器显示精确的 wire 格式，分析器和模型目录测试都会断言路径与请求头。未知持久化值回退到 Chat Completions。
- [分析期间设置变化] → 每个请求在开始时快照 protocol、endpoint、key 和 model；后续请求读取最新设置。正在进行的请求不会被中途修改，并可通过正常请求 token 取消。
- [敏感的模型获取错误] → 在转换为诊断细节前截断并脱敏响应体；本地化 UI 只接收稳定的失败分类。
- [UI 本地化漂移] → 同时向中性资源文件和 `zh-CN` 资源文件增加键，并保留本地化覆盖测试。

## 迁移计划

1. 使用现有键发布新 UI；不需要设置迁移。
2. 如果不存在 `LlmProtocol`，显示 OpenAI Chat Completions，并且只在用户修改或保存后持久化该值。
3. 现有手动填写的 endpoint、key 和 model 值继续由新分析器使用。
4. 回滚只涉及代码：设置文件仍然兼容，因为所有键都是现有扁平字符串字段；模型目录结果不会持久化。
