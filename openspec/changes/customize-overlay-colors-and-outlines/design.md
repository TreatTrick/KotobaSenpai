## Context

现在 `WpfOverlayRenderer` 把颜色写死在代码里。普通振假名和下划线还共用同一个蓝色画刷。振假名带固定的黑色阴影，圆点和下划线没有统一的描边设置。

设置页已经有 Windows 11 风格的卡片，也有共用的设置服务和 WPF-UI 控件，可以继续使用。

## Goals / Non-Goals

目标：
- 分别设置普通振假名、H 高音、L 低音和普通下划线的颜色。
- 描边可以开启、关闭，默认自动选择黑色或白色，也能手动固定黑色或白色，并调整粗细。
- 设置自动保存，预览和已有标注及时更新。
- 保持原有字号、位置、音调、悬停和点击穿透行为。

本次不做：
- 不提供任意 RGB 描边色或透明度设置。
- 不修改游戏原文，也不修改释义弹窗内的卡片配色。
- 不增加主题预设、独立配置文件或新的设置存储服务。
- 平板型小横杠和鼠标悬停强调继续使用现有填充色。

## Decisions

### 1. 四个填充颜色设置，以及描边偏好

| 设置 | 用途 | 默认值 |
| --- | --- | --- |
| `OverlayFuriganaColor` | 没有有效音调时的普通振假名 | `#00BFFF` |
| `OverlayPitchHighColor` | H 高音文字和圆点 | `#FF4444` |
| `OverlayPitchLowColor` | L 低音文字和圆点 | `#4488FF` |
| `OverlayUnderlineColor` | 鼠标未悬停时的下划线 | `#00BFFF` |
| `OverlayOutlineEnabled` | 是否绘制描边 | `true` |
| `OverlayOutlineColorMode` | 描边颜色模式：`auto`、`black`、`white` | `auto` |
| `OverlayOutlineThickness` | 描边向外扩展的逻辑宽度 | `1` DIP |

默认颜色保持不变。描边默认开启，用户可以关闭。没有这些新设置的旧配置也使用默认值。普通振假名与下划线分别取色，不再因为共用画刷而一起改变。

只接受不透明的 `#RRGGBB` 颜色。保存时统一为大写。设置文件里缺失或损坏的值使用对应默认值，不影响其他设置。

### 2. 默认自动描边，也能手选黑白和粗细

开启描边并选择“自动”时，分别计算每个标记填充色与黑色、白色的对比，选对比更强的颜色。例如黑字配白边，白字配黑边。结果相同时选黑色。用户也可以选择“黑色”或“白色”，覆盖自动结果；切回“自动”后重新按每个标记的实际填充色计算。

计算只看标记自己的填充色，不采样游戏背景。修改 H 颜色不会改变 L 的描边。下划线进入悬停色后，也按实际悬停色选描边。

关闭描边时，文字、圆点和线条都不画描边，也不保留旧的黑色阴影，颜色模式和粗细的选择则保留。开启时使用清晰的实线描边，不用模糊发光代替。粗细范围为 0.5～3 DIP，滑块步长为 0.25，默认 1 DIP，随系统缩放。设置文件中的非法模式回退为“自动”，非法或越界粗细回退为 1 DIP，保存小数使用统一格式。

自动模式延续原有行为，手选黑白和粗细用于适配不同背景。只增加这两个偏好，不增加任意 RGB 描边色。

### 3. 设置页继续使用现有卡片

在“标注外观”分组中放置四个颜色项、描边开关、颜色模式下拉框、粗细滑块、小预览和“重置颜色”按钮。颜色模式和粗细各占一张卡片，关闭描边时控件置灰，但保留选择。按钮放在预览卡片内，点击后一次恢复四种初始颜色；所有描边偏好保持原样。

颜色项显示色块和十六进制值。点击色块后，打开类似 Photoshop 的颜色面板：左侧是二维颜色区，横向选择饱和度，纵向选择明暗；右侧用竖直色相条选择颜色种类。保留 HEX 输入，和色盘双向同步。鼠标支持点击、拖动，键盘支持方向键微调与 Shift 加方向键大步调整。选择器内确认后保存，取消则保留原色。手动输入非法颜色时，在当前卡片里提示，不覆盖已保存的颜色。

实施时确认 [WPF-UI 4.3.0 的 `ColorPicker`](https://github.com/lepoco/wpfui/blob/4.3.0/src/Wpf.Ui/Controls/ColorPicker/ColorPicker.cs) 只有空类，没有可用的选色功能，因此使用 WPF 自带渐变、鼠标捕获、滑块和现有 Fluent 按钮组成面板，不增加第三方依赖。HSV 与 RGB 的转换只属于 App 选色控件，不放入 Core 设置模块。黑色、灰色没有唯一色相，选色时保留用户刚选择的色相，避免标记跳动。

预览展示普通振假名、H/L 文字与圆点、下划线。它使用与覆盖层相同的颜色和描边规则。所有操作反馈都在所属卡片内，不在卡片外追加文字。

界面文案提供中文和英文，跟随当前界面语言。卡片和控件跟随深浅主题；用户选定的标注颜色不因主题切换而改变。

### 4. 复用设置服务，保存后只刷新外观

Core 保存设置键、默认值、颜色检查和自动黑白颜色计算，不引用 WPF 类型。App 负责颜色编辑和保存。Windows 绘制层把有效颜色转换为画刷，并绘制文字、圆点和下划线。

继续使用 `ISettingsService`。一次读取完整外观快照，避免一半使用旧颜色、一半使用新颜色。“重置颜色”一次保存四项默认颜色，不改描边开关、模式、粗细、主题、字号、API 等其他设置。`OverlayAppearanceViewModel` 由 DI 容器创建并注入设置页。

保存成功后，由 App 组合根把外观变更通知交给覆盖层。ViewModel 不直接依赖 Windows 绘制类。覆盖层更新已有会话的外观，不重新 OCR、分词或请求 AI，也不关闭当前释义弹窗。

覆盖层尚未创建或暂时隐藏时，保留新外观；下次显示时直接使用。无需给通用设置服务增加文件监听或跨进程通知。

### 5. 保持原有绘制位置和交互

文字使用真实字形轮廓绘制描边。圆点和线条使用对应的边线。预览和覆盖层复用这部分逻辑，避免两套效果不一致。

描边只增加外观边缘，不改变词框、拍位置或下划线的命中区域。透明窗口按最大 3 DIP 提前留出边缘空间，粗细变化时无需移动窗口或重建会话，避免边缘被裁掉。颜色和描边调整不清空词义、音调或当前会话。

## Risks / Trade-offs

- 小字号加描边可能显得拥挤 → 默认 1 DIP，限制在 0.5～3 DIP，并检查小字号和不同 DPI。
- 每拍重复创建字形和画刷可能增加开销 → 复用同一外观快照的画刷，悬停时不重复生成文字字形。
- 预览和实际覆盖层可能不一致 → 使用同一套颜色检查、自动黑白选择和描边绘制逻辑。
- 保存失败可能让界面误报成功 → 保留原设置与原标注，在当前卡片中显示错误。

## Migration Plan

新设置都是可选字段，不需要转换旧配置。缺少字段时使用表中的默认值。“重置颜色”只恢复四项填充颜色，不重置描边开关、颜色模式或粗细。

## Open Questions

没有待确认项。描边支持开关、自动或手动黑白颜色，以及粗细调整。
