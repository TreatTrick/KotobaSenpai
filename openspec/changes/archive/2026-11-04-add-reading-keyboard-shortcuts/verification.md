# 快捷键验收记录

验证日期：2026-11-04。环境：Windows、.NET SDK 10.0.103。

## 已实现

默认 F1 识别、F2 开关自动识别、F3 停止并清除、F4 隐藏并暂停／恢复、F5 框选。设置页可以录制、取消绑定、恢复单项默认值，并显示冲突或保存错误。识别页的五项操作旁显示实际键位，改绑后立即更新。

系统按键接收放在 Windows 层；绑定与保存交给 `ReadingShortcutCoordinator`；按钮和快捷键共用 `ReadingActions`；识别、取消和恢复由 Core 的 `RecognitionSessionController` 管理。没有增加外部依赖。

构造设置页面只读取绑定，不创建识别运行环境。应用启动时在 UI 线程调用快捷键协调器的 `Start()`，OCR 准备完成后才接入阅读动作。退出先停止接收动作，再取消并等待会话任务，最后释放按键。

## 行为检查

- 会话测试验证隐藏后不再识别或发送新模型请求，排队句段不会继续发出，取消后晚到的结果不能显示或写入缓存。
- 恢复时先检查当前画面和位置；相同台词复用分析，新台词才重新分析。多句中已完成的一句立即保留缓存，暂停后只重试未完成的句子；这项测试先复现了重复请求，再验证修复。
- 最小化、遮挡或本地检查失败时保持隐藏；空画面可以安全恢复；停止后不能恢复旧会话。真实 WPF 显示窗口在隐藏后经历目标恢复、移动和外观刷新也不会自行显示。
- 按钮与快捷键共用的动作测试覆盖 F2 保留结果、隐藏期间只保存自动识别偏好、F1 提示先恢复、框选期间只允许停止，以及停止关闭未确认的框选。
- 真实 `RegisterHotKey` 和系统按键输入验证 F1～F5、长按去重、自定义组合键、改绑及取消绑定。测试主窗口保持最小化，前台窗口不被替换。
- 独立测试进程占用 `Ctrl+Alt+Shift+F11`，验证启动和修改时得到占用错误，原绑定仍可用；占用进程退出后可以改绑。注销后另一个注册器能重新占用原键。
- 设置测试覆盖无效格式、重复键、写入失败回退、取消绑定后的重启，以及后续注册失败不会被旧的成功提示掩盖。
- 中英文、明暗主题、长组合键、100% 和 150% 图片检查通过。录制控件复用 FluentLight 按钮样式，圆角一致；五项键位标签不获取焦点，辅助功能说明读取同一份绑定。
- 架构测试包含 `Core/Shortcuts`，并检查 Core 不引用 WPF/App、Windows 按键接收不依赖 App 或识别流程。退出等待和旧会话不干扰新目标预览也有回归测试。

桌面预览由测试生成在 `tests/KotobaSenpai.App.Tests/bin/Debug/net10.0-windows10.0.19041.0/previews/shortcuts-*.png`。

这些检查使用真实 Windows 消息和显示窗口，以及可控制完成时机、可统计调用次数的识别／模型替身；没有使用付费 API，也没有逐个游戏测试游戏自身的按键冲突。

旧桌面测试同时修正了过期的默认透明度断言，并把拥有 WPF Application 的检查移到子进程，避免关闭 Application 影响其他测试。支持弹窗的前台焦点断言仅在 Windows 允许测试窗口获得焦点时执行。
