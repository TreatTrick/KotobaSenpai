## Context（现状）

目前识别页已有识别按钮、自动识别开关、框选区域按钮和“隐藏”按钮。这里的“隐藏”实际会停止自动识别、取消当前任务并清除结果，没有保留结果的临时隐藏操作。应用也没有统一的后台快捷键处理。

已有识别流程会先显示本地振假名，再补充云端分析得到的词义和短语。窗口被最小化或遮挡时，系统能够保留结果，恢复可见后再显示。新增主动隐藏要与这些规则配合，不能因为来了新结果就把标注重新显示出来。

## Goals / Non-Goals（要做什么）

**目标：**

- 用户留在游戏或阅读器中，就能完成选定的五项操作。
- 按钮与快捷键行为一致，能明确区分暂停、隐藏和停止；主动隐藏时不为新识别继续消耗模型额度。
- 用户能修改或取消绑定，按键冲突和保存失败都有明确反馈。
- 继续使用现有识别、窗口跟随、设置和 FluentLight 能力。

**本次不做：**

- 查词按住键、弹窗固定、复制、目标切换和 Anki 快捷键。
- 仅运行本地注音、跳过云端分析或其他新的识别模式。
- 鼠标快捷键、连续多次按键、单独使用 Shift 等修饰键触发操作。

## Decisions（具体做法）

### 1. 五项操作各有固定含义

| 操作 | 默认键位 | 按下后的行为 |
| --- | --- | --- |
| 识别／重新识别 | `F1` | 对当前目标识别一次；自动识别已开启时，完成后继续自动识别；主动隐藏期间提示先恢复阅读 |
| 开启／暂停自动识别 | `F2` | 开启时按需先识别一次；暂停时保留屏幕上的结果；主动隐藏期间只改变偏好，不启动识别 |
| 停止识别并清除标注 | `F3` | 停止当前识别，清除结果、标注和释义弹窗 |
| 临时隐藏并暂停／恢复阅读 | `F4` | 隐藏并暂停全部识别，保留结果与缓存；恢复时检查当前画面并优先复用缓存 |
| 重新框选识别区域 | `F5` | 打开现有区域选择器，不新建另一套框选界面 |

默认直接使用单个功能键，一次按一个键即可，不需要 Ctrl 或 Alt，也不依赖数字小键盘。参考 [DokiDokiDict 的默认快捷键](https://dokidokidict.com/guide.html)，其单次注音、连续注音、清除标注同样使用单键；本项目用 F1～F5 覆盖选定的五项操作。

自定义支持单个 F1～F11，也支持带 Ctrl、Alt 或 Shift 的组合键，不强制使用多键组合。单独修饰键、裸字母和裸数字仍不作为本次支持范围；F12 是 Windows 调试保留键，本次不绑定。

设置中的自动识别开关表示用户偏好，识别页状态另外说明“尚未开始”“自动识别中”“已暂停”“已隐藏并暂停”或“已停止”。例如，主动隐藏或停止识别后可以保留自动识别偏好，但不能继续显示为正在运行。隐藏后按 F4 恢复阅读；停止清空后需要重新开始识别。

### 2. 快捷键调用现有操作，识别状态只维护一份

Windows 层负责接收按键，应用层把它转成五项操作之一，交给共用的 `ReadingActions`。识别页命令也调用这一入口，由会话控制器执行识别操作；不通过快捷键直接调用 ViewModel，也不各自维护一套识别流程。

主窗口在后台或最小化时也保持快捷键可用，操作不会把主窗口抢到前台。首次引导未完成、正在拾取目标窗口或正在录制快捷键时，暂停执行这五项操作。框选区域期间只允许“停止识别并清除标注”，它也会关闭区域选择器且不保存尚未确认的修改。

长按组合键只执行一次，松开后才能再次触发。一次手动识别未完成时，再按识别键不排队启动第二次；停止键始终能够取消当前识别。自动识别任务运行时请求手动刷新，则先停止旧的自动任务，再执行一次手动识别。

相比仅给 WPF 页面增加按键绑定，后台快捷键可以覆盖游戏保持焦点的主要场景；相比监听所有键盘输入，系统快捷键注册只需处理已绑定按键，也更容易发现占用冲突。单个功能键可以使用同样的注册方式，不需要为此改成三键组合。

### 3. 主动隐藏时暂停识别，保留结果以便恢复

为当前目标的阅读会话保存一个“已隐藏并暂停”的状态。它同时控制识别和显示，三个操作的区别如下：

| 操作 | 屏幕标注 | 识别任务 | 已有结果和有效缓存 |
| --- | --- | --- | --- |
| F2 暂停自动识别 | 保留显示 | 停止自动任务，不取消独立手动任务 | 保留 |
| F4 隐藏并暂停 | 全部隐藏 | 停止自动检测，取消未完成的手动和自动任务 | 保留 |
| F3 停止并清除 | 全部清除 | 停止并取消全部任务 | 清除可恢复的会话结果 |

按下 F4 后，关闭标注、释义弹窗和被动识别提示，停止悬停交互，停止新的捕获采样和本地识别，并向未完成的识别和模型请求发出取消信号。已经取消的任务即使晚到，也不更新保存结果、不显示标注、不启动后续分析或重试。保留隐藏前已经完成的结果和有效缓存，不清空用户的自动识别偏好。

已经发往模型服务的请求可能仍产生费用，取消不能保证撤销已发生的消耗；本功能保证隐藏后不再启动新的模型请求和重试。

隐藏期间，F1 提示“请先恢复阅读”，不偷偷执行识别；F2 只调整恢复后的自动识别偏好；F5 可以沿用区域选择，但确认区域不启动识别。窗口移动、恢复可见、设置变化及显示窗口重建都不能自行恢复识别或标注。

```text
允许显示标注 = 结果仍有效
             且目标满足原有可见条件
             且用户没有主动隐藏
```

再次按 F4 时，先确认目标能够正常显示，再对当前画面执行一次本地识别，按新位置匹配已有结果：

- 句段原文、释义语言等符合现有缓存规则且已有成功分析：直接复用，不再次调用模型。
- 当前画面包含新台词，或者上次分析被取消、失败、缺失：只对没有有效缓存的句段调用模型。
- 完成这一次恢复检查后，根据当前自动识别偏好决定是否继续自动检测；原来关闭自动识别时，不自动改成开启。

恢复不能直接显示隐藏前的旧标注，因为隐藏期间游戏可能已经换了台词。也不能直接调用会清空缓存的完整手动刷新流程，否则同一台词会白白重复消耗额度。目标仍不可见、最小化或遮挡超出原有显示条件时，保持隐藏和暂停，提示恢复目标后再次请求；本地检查失败时同样保留暂停状态和已有结果，允许重试。本地检查成功但模型分析部分失败时，继续沿用现有的部分结果和错误提示规则。

暂停状态必须独立于绘制标注的 WPF 窗口保存。取消未完成任务时，只拒绝该任务后续返回的结果，不把隐藏前已经保存的结果一并清除。恢复检查使用新的任务标记，防止隐藏前的旧任务在恢复后覆盖新画面。

停止识别、目标被销毁、切换目标或退出应用时，清除主动隐藏状态。它不写入设置文件。没有正在执行、已暂停或保存了结果的会话时，F4 不建立一个影响未来识别的暂停状态；首次识别被 F4 暂停但尚未产生结果，仍属于可恢复的暂停会话。窗口仅因原有遮挡、最小化规则暂时隐藏时，继续遵循原有规则，不把它等同于用户主动按 F4。

### 4. 主动开启自动识别可以直接开始阅读

用户通过开关或快捷键把自动识别从关闭改为开启时：

- 已主动隐藏：只更新偏好，实际识别继续暂停，等待用户恢复阅读。
- 有可用目标且没有识别会话：先调用已有手动识别流程，成功后开始自动检测。
- 已有会话：开始自动检测；已有手动识别正在进行则等待它结束，不重复启动。
- 没有可用目标：保存开启偏好并提示先选择或恢复目标，不自动选择窗口。

读取启动设置、选择窗口和重试预览都不算用户发起识别，仍然不能自动开始。暂停自动识别时停止采样、取消尚未完成的自动任务，保留最后已显示的结果；单独正在执行的手动识别不受影响。

### 5. 绑定设置按操作保存，失败时保留旧绑定

每项操作保存自己的键位，区分单键与带修饰键的组合；缺少设置表示使用默认值，明确清空表示不绑定，不能把两者混为一谈。所有读写都使用 `ISettingsService`，不直接读写设置文件。

录制时暂停功能执行，并确保录制控件也能收到当前已绑定的组合键，按下组合键后显示待保存结果；Esc 取消录制，清空按钮取消绑定。保存前检查格式、重复绑定和系统占用。单项修改或恢复该项默认值时，先尝试新绑定并保存；成功后再移除旧绑定。若失败，则释放试用的新绑定，保留旧设置和旧绑定。取消绑定同样先保存成功再释放旧绑定，保存失败时不改变原状。

启动时某一项被其他程序占用，只把该项标为“未生效”，其他项照常运行，不自动改成另一组键。用户修改后可以重新尝试。退出应用时注销已注册的组合键。录制结束后要等相关按键松开，不能把刚录制的组合键当成一次功能操作。

### 6. 界面入口与项目现有风格一致

设置页增加“键盘快捷键”区域，每项显示操作名称、当前键位、修改、取消绑定、恢复该项默认值和生效状态。识别页新增“隐藏并暂停／恢复阅读”按钮；原“隐藏”按钮改为“停止识别并清除标注”。

五项操作都在对应按钮或开关旁常驻显示当前快捷键，让用户看到操作就能知道怎么按，不要求先去设置页查找或停留鼠标。参考用户给出的菜单示例，操作名称和键位分开排布：

```text
识别当前画面                F1
开启／暂停自动识别          F2
停止识别并清除标注          F3
隐藏并暂停／恢复阅读        F4
设置识别区域                F5
```

在现有设置卡片中，键位放在操作按钮文字右侧或紧邻按钮的位置；自动识别的键位放在开关旁，不拼进“开／关”文字。如果同一操作在菜单中出现，键位在菜单项右侧对齐。五项入口复用统一的键位展示样式，使用与主题匹配、清楚可读的次要文字或轻量按键外观，与操作名称留出间距。较长组合键和中英文界面都应完整显示，必要时调整布局。

展示始终读取快捷键协调器的当前绑定快照，不在 XAML 或本地化资源中写死 F1 等默认值。例如用户将识别改为 Ctrl+H 后，按钮旁立即改成 Ctrl+H。取消绑定后去掉入口旁的键位，设置页显示“未绑定”；注册失败则保留已配置键位并附“未生效”标识。按钮仅因无目标或正在执行而暂时禁用时，仍保留可读的键位，提示暂时不可用的原因，不把它误标为注册失败。

F4 在“隐藏并暂停”和“恢复阅读”之间切换名称时，仍显示同一项当前绑定；自动识别开关的开关状态变化也不改变对应键位。鼠标提示和辅助功能说明可补充键位与原因，不能替代常驻展示。键位标签只负责展示，不额外注册按键、不执行操作，也不增加单独的键盘焦点。

所有新内容放在现有主窗口的 FluentLightHost 下，复用 SettingsCard、按钮和输入样式，圆角与实际控件一致。错误反馈放在页面内，不为常规冲突新开窗口。界面文案放入各语言 `.resx` 文件；代码注释、测试名和日志继续使用英文。

### 7. 快捷键接收、阅读操作和识别会话分开维护

目前 `RecognitionPageViewModel` 同时持有识别任务的取消对象、会话编号、自动识别状态和显示状态。若直接把按键判断也加进去，后续修改暂停、恢复或设置时都会牵连同一个类。本次先把运行中的阅读会话整理出来，再接入快捷键。

考虑过两种接法：

| 接法 | 优点 | 代价 |
| --- | --- | --- |
| 独立接收按键，然后调用现有 ViewModel 命令 | 改动较少，五个动作能很快接上 | 取消、恢复和后台任务仍集中在 ViewModel，快捷键也要跟着页面命令结构变化 |
| 独立接收按键，按钮和快捷键调用共用操作入口，会话逻辑独立维护 | 键位、界面和识别各自修改，暂停取消可以脱离页面测试 | 需要先从 ViewModel 提取已有会话逻辑 |

本提案采用第二种。新增模块只围绕这五项操作，使用普通方法调用和少量状态通知，不引入通用命令总线、消息中间件或新的框架。

```text
Windows 按键
    ↓
Win32GlobalShortcutRegistrar（接收按键、报告注册编号）
    ↓
ReadingShortcutCoordinator（查找该编号对应的阅读动作）
    ↓
IReadingActions / ReadingActions ← 识别页按钮和开关
    ├─ 识别、自动识别、停止、隐藏恢复 → RecognitionSessionController
    │                                   ├─ WordOverlayApplicationService
    │                                   ├─ IAutoRecognitionController
    │                                   └─ IOverlayRenderer
    └─ 框选区域 → 现有 IRegionSelector

快捷键设置界面 → ReadingShortcutCoordinator → IGlobalShortcutRegistrar
                                           → ISettingsService
```

上图表示运行时调用关系；代码依赖继续向 Core 汇聚。各块的职责和放置位置如下，名称均为计划新增：

| 模块 | 放置位置 | 负责什么 | 不负责什么 |
| --- | --- | --- | --- |
| `ShortcutGesture`、`IGlobalShortcutRegistrar` | `Core/Shortcuts` | 描述按键和修饰键，约定注册、注销、触发通知和失败原因 | 不包含 WPF 的 Key、窗口句柄和五项阅读操作 |
| `Win32GlobalShortcutRegistrar` | `Platform.Windows/Shortcuts` | 转换 Windows 键码，接收系统消息，处理长按和注册资源释放 | 不认识 ViewModel、OCR、模型、设置页或“隐藏阅读”业务 |
| `ReadingShortcutCoordinator` | `App/Shortcuts` | 保存五项动作的绑定、处理改绑和冲突，把触发编号对应到阅读动作 | 不保存识别状态，不直接截图、取消模型或操作浮层 |
| `IReadingActions`、`ReadingActions` | `App/Reading` | 提供五项共用操作；检查引导、窗口拾取、录制和框选等交互限制，读取现有选择并调用会话或区域操作 | 不实现 OCR、缓存或 Windows 按键处理 |
| `RecognitionSessionController`、状态快照 | `Core/Workflow` | 统一管理当前会话、自动识别偏好、运行阶段、取消、隐藏暂停和恢复 | 不知道键位、页面、中文资源键或首次引导界面 |
| `ShortcutSettingsViewModel`、录制控件 | `App/ViewModels`、`App/Controls` | 显示当前绑定，采集用户输入，展示错误和成功状态 | 不直接注册系统快捷键或读写设置文件 |

`Core/Shortcuts` 只放与平台无关的输入约定。把它补充进现有 `CoreSliceArchitectureTests` 的基础层列表，确保新目录也受依赖检查，不能因为新增目录而绕开规则。Windows 层继续只依赖 Core，不能引用 App。

#### 7.1 共用入口只保留一份操作规则

识别页的命令和快捷键协调器都依赖 `IReadingActions`，由同一个 `ReadingActions` 实例处理。接口只描述本次明确支持的五项操作及其可用状态，不做可随意注册命令的扩展平台。

引导未完成、正在拾取窗口、正在录制等界面限制在这里统一检查；按钮可用状态也从同一份判断获得。执行前还要重新检查，避免判断后状态已经改变。Core 会话控制器独立守住隐藏暂停、取消和结果有效性，即使以后增加其他入口，也不能绕过这些规则。

当前目标仍由 `TargetSelectionViewModel` 维护，动作入口只读取已提交选择，不另建一份可变选择。提交新目标时先结束旧会话。区域选择复用现有 `IRegionSelector`，停止动作同时关闭未确认框选，不把区域窗口细节塞进 Core 会话控制器。

#### 7.2 运行状态只有会话控制器能够修改

将 ViewModel 中现有的会话运行状态、手动任务取消和会话编号迁入 `RecognitionSessionController`。ViewModel 读取状态快照，将其转换为本地化文案和按钮状态；快捷键协调器只读取动作是否可用，不再维护第二套“正在识别”或“已经隐藏”的布尔值。

会话控制器决定能否开始、暂停或恢复；现有 `WordOverlayApplicationService` 继续负责一次识别的捕获、分词、缓存匹配、分析和结果发布。前者管理整段阅读过程，后者执行其中一轮，不合并为一个包办全部功能的类。

保留两种已有保护的不同职责：会话编号防止旧目标、已停止或已暂停的任务继续生效；识别流程内部的轮次检查防止旧一轮结果覆盖新一轮。取消信号要传递到捕获、排队句段和模型请求，发请求前再次检查。取消和状态变更立即完成，耗时识别不占用状态变更的锁，避免 F4 或停止键必须等待模型返回。

显示层可以保存绘制需要的几何数据，但不能自行决定恢复业务运行。当前 `IOverlayRenderer.Hide()` 会清理会话，需要补充明确的“保留结果并暂停显示”入口，不能拿清空方法代替暂停，也不能让渲染器负责取消模型。

#### 7.3 改键和设置由快捷键模块统一提交

设置页不直接操作 Windows 注册。它把新键位交给 `ReadingShortcutCoordinator`，后者统一规范化、查重、尝试注册，再通过 `ISettingsService` 保存；成功后切换当前绑定并释放旧注册。失败则保留旧设置和旧绑定，页面只显示返回的结果。

动作使用固定标识，显示名称单独本地化，切换语言不能改变保存键或动作映射。Windows 注册编号只是输入凭据，不使用资源文案或 ViewModel 方法名作为动作标识。快捷键设置、注册结果和入口旁的键位标签都读取协调器发布的同一份绑定快照；键位格式统一转换为 F1、Ctrl+H 等可读文字，显示标签不参与注册或派发。

#### 7.4 轻量启动，完整退出

当前 `App.PrepareRuntimeAsync` 在引导过程中才创建 OCR 和识别页。快捷键设置与注册服务不能在构造时解析 `RecognitionPageViewModel`、会话控制器或 OCR 服务。先创建轻量快捷键模块，运行环境准备完成后显式接入 `IReadingActions`；接入前不执行阅读操作。注册器、快捷键协调器、共用动作和会话控制器沿用现有单例组装方式，每个应用进程只有一份；页面切换不重新注册按键。退出时先停止接收新动作，再取消并等待会话任务，最后注销按键和释放系统消息资源。

现有 `MainWindowViewModel.StopAsync` 主要等待页面命令的执行任务。重构后，要等待会话控制器实际跟踪的任务，覆盖快捷键和自动检测启动的工作；不能只等待按钮命令。依赖的创建与连接仍集中在 `App.xaml.cs`，不在业务类里使用全局服务查找。

系统按键回调只安排动作，不在消息回调中等待 OCR。界面相关调用在 UI 线程执行，Core 仍不引用 Dispatcher。会话状态通知由 App 转回界面线程。重构同时保留预览与识别共用捕获服务的保护：旧会话清理不能停止新目标正在获取的预览。

#### 7.5 用行为测试守住模块边界

- 快捷键模块使用假的注册器和阅读动作入口，验证一次按下只派发一次正确动作，改绑失败旧键仍可用，不需要加载 OCR。
- 会话控制器使用已有捕获、模型、自动检测和显示替身，验证隐藏后零新请求、旧结果失效、恢复缓存复用以及停止不被模型等待阻塞。
- ViewModel 验证状态与本地化展示；设置页验证录制、改绑和错误反馈，不重复测试整条 OCR 流程。
- Windows 适配器验证真实消息、冲突和注销；架构测试检查 Core 不引用 WPF 或 App、Windows 不引用 App，输入接收模块不依赖识别流程。

## Risks / Trade-offs（可能遇到的问题）

- 默认按键可能被其他软件注册占用 → 显示具体受影响操作，允许改绑或取消绑定，不影响应用启动。
- 游戏或阅读器本身也可能使用 F1 等按键，系统注册成功不能证明没有这种冲突 → 允许用户改为其他功能键、组合键或取消绑定，不宣称能自动发现游戏内所有按键冲突。
- 隐藏期间旧请求返回或窗口恢复 → 取消旧任务、阻止后续请求，识别和显示两处都检查暂停状态，并测试先后顺序。
- 恢复时游戏已换台词，或者上次分析只完成一部分 → 先本地检查当前画面，再复用有效缓存或补充缺少的分析，避免旧标注错位和重复计费。
- 停止后旧任务才完成 → 保留现有“只接收当前识别结果”的保护，不能重新显示或恢复自动检测。
- 快捷键录制触发了功能操作 → 录制期间暂停处理，结束后等待松键。
- 用户分不清开关偏好和实际运行 → 主动隐藏时明确显示“已隐藏并暂停”，即使自动识别偏好仍开启，也不显示为正在运行。

## Migration Plan（如何接入和回退）

旧设置没有快捷键条目时使用默认绑定，自动识别原有偏好保持有效。临时隐藏只在本次会话中存在，不迁移或持久化。现有“隐藏”的停止语义保留，只把名称说清楚。

实现时先提取会话控制器并保持原行为，再接入共用阅读操作、隐藏暂停和恢复，随后增加 Windows 快捷键及设置界面。回退快捷键入口时可以保留会话控制器和共用操作，按钮仍正常工作；若整项功能回退，再移除隐藏恢复入口和新增设置读取，残留设置条目由现有设置机制忽略。

## Open Questions（待确认事项）

当前没有阻碍实现的问题。默认键位先按上表执行；如果用户希望调整，在实现前统一修改本设计和快捷键规格。
