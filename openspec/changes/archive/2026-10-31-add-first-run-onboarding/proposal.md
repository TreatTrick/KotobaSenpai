## Why

首次启动时，应用先在主界面上阻塞下载词典，随后直接进入识别页，用户仍需自行发现设置页并完成大模型配置。将必要准备串成四步引导，让首次使用明确结束于选择目标并开始识别，避免用户进入尚不可用的识别界面。

## What Changes

- 在同一 Fluent 应用窗口内提供首次使用引导：准备词典、配置大模型、选择窗口、开始识别；完成前隐藏常规识别和设置导航。
- 按已确认的 HTML 原型，以原生 WPF 落地简洁双栏、大标题、圆点步骤、固定底部操作和轻柔切步动效；模型表单与目标预览使用引导专用呈现，复用真实配置、捕获与识别状态。
- 引导外壳始终提供界面语言切换，四步及准备、错误状态均可即时切换并记住偏好，保留步骤和在途操作。
- 第三步允许返回第二步，第四步允许返回第三步；第二步不提供返回词典步骤的入口，步骤条仅展示进度。返回保留已保存配置和当前会话内仍有效的目标，不触发下载或识别。
- 词典步骤显示下载、校验、解压和安装阶段，支持错误反馈与重试；保留固定资源、完整性校验和原子安装约束。
- 模型步骤与现有模型设置保持一致，提供 AI 返回语言（释义语言）输入与保存、Agent 辅助配置、手动配置、模型获取和真实分析检测；语言沿用已有默认跟随和独立保存规则，当前连接配置验证通过才允许继续，不提供跳过。
- 选窗步骤复用现有桌面拾取、静态预览和目标可用性反馈；选窗不触发识别。
- 最后一步确认模型和窗口，点击“开始识别”后完成主界面交接并发起一次识别；空结果和请求失败在主界面处理。
- 持久化引导状态，未完成时根据实际准备状态恢复；外部配置工具退出并恢复 GUI 后仍回到模型步骤。已完成用户后续启动直接进入主界面。
- 升级时对无引导记录、词典已就绪且当前模型验证指纹匹配的已有安装执行一次兼容迁移；明确记录过未完成引导的安装不得被此规则绕过。

- 流程由独立显式状态机集中管理状态、事件、准入和副作用；ViewModel 只适配命令和文案，宿主按当前步骤切换一个完整视图，保留已确认的视觉及共享配置/目标实例。

## Capabilities

### New Capabilities

- `first-run-onboarding`: 首次四步引导、AI 返回语言设置入口、步骤准入、恢复、升级迁移和识别交接。

### Modified Capabilities

- `japanese-tokenizer`: 将启动安装承载于词典准备步骤或已完成用户的修复入口，并公开准确的安装阶段。
- `llm-settings`: 在引导和设置页提供一致的返回语言、Agent 配置与手动配置入口，共用连接配置和验证状态，支持配置后恢复到相应入口。
- `visual-window-picker`: 支持引导与识别页两种宿主，预览落入当前可见页面，交接时保留同一选择。
- `agent-api-configuration`: 外部配置工具恢复 GUI 时，未完成引导的用户返回模型步骤且不被误判为已完成。

## Impact

- App：调整 `App.xaml.cs` 的启动与运行时装配边界、`MainWindow` 的内容切换，增加引导状态协调和页面；窗口负责承载，协调器只依赖能力状态与明确操作入口，不引用具体页面或依赖注入容器。沿用现有 MVVM、Fluent 资源与 `.resx` 本地化。
- 词典：扩展 `UniDicInstallController` / `UniDicDictionaryInstaller` 的阶段反馈，不改变固定资源、缓存布局或校验规则。
- 模型与选窗：复用 `LlmSettingsViewModel`、`LlmConfigurationService`、现有 `IExplanationLanguagePreferences` 及语言保存行为。从 `RecognitionPageViewModel` 最小提取目标选择与预览模块，供引导和识别页组合使用，沿用现有捕获/跟踪端口；明确共享状态、页面呈现及捕获操作的释放所有权，避免双重订阅。首次识别通过明确的能力入口交接。
- 设置：通过 `ISettingsService` 保存一个引导状态键，不新增持久化文件、跨进程监听或 CLI 命令。
- 验证：增加启动路由、恢复、门禁和交接测试，回归下载、模型配置与窗口预览生命周期，并完成 WPF 手工验收。应用代码、注释、测试和诊断继续遵守英文约束。
