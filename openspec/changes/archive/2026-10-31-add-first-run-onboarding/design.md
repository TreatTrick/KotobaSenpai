## Context

`App.OnStartup` 目前先创建并显示 `MainWindow`，通过独立的 `InstallController` 属性显示下载遮罩。词典安装完成后，`InitializeRuntime` 才构造 OCR、分词器和 `MainWindowViewModel`；词典未就绪时无法安全地依赖完整识别对象图。下载进度达到 1 发生在校验和解压之前，现有遮罩不能区分这些阶段。

`LlmSettingsViewModel` 已有即时保存、模型目录、当前配置检测和验证状态；`LlmConfigurationService.GetStatus().Verified` 依据当前配置的指纹判断已有检测记录是否匹配。外部 CLI 配置会正常关闭并重新打开 GUI。`RecognitionPageViewModel` 已管理窗口拾取、预览捕获和目标跟踪，但隐藏宿主、图片飞入和静态图片持有目前位于识别页代码中，不能仅在引导里绑定同一个命令而忽略这部分生命周期。

## Goals / Non-Goals

**Goals:**

- 首次使用在同一窗口内完成词典、模型、选窗、开始识别四步；模型步骤提供与设置页一致的 AI 返回语言、Agent 辅助配置和手动配置，连接检测通过是继续的必要条件。
- 引导可退出、重试并恢复，外部 AI 配置重启后保留第二步上下文。
- 完成后后续启动直接进入主界面；首次识别的空结果或运行时故障不重开引导。
- 复用下载、模型验证和识别工作流，保持选窗捕获、动画和资源释放约束。

**Non-Goals:**

- 不增加服务商账户注册、套餐购买、模型推荐服务、离线识别模式或独立配置存储。
- 不实现断点续传、并行后台配置、跨进程热更新、引导重播或复杂的通用向导框架。
- 不在引导中要求调整区域、自动识别或外观；这些保留在主界面设置中。AI 返回语言属于模型步骤，用户可以沿用默认跟随值，无须额外填写。
- 不改变词典资源和目录覆盖约定、LLM 请求协议、模型选择规则或现有自动识别偏好。

## Decisions

### 1. 同一 Fluent 窗口承载引导和主界面

`MainWindow` 保留主题、标题栏和应用退出所有权，内容分为启动准备、首次引导和常规主界面。使用一个轻量 App 层协调器管理路由和步骤；其构造只依赖设置、词典状态和已有模型配置服务，不解析词典依赖的识别对象图。引导期间不实例化隐藏的常规页面来绕过初始化顺序。

各部分的职责与依赖限制如下：

| 部分 | 职责与限制 |
|---|---|
| `MainWindow` 与页面视图 | 承载当前内容，处理布局、焦点、窗口隐藏/恢复及动画；不决定步骤准入、校验配置或解析运行时依赖 |
| `OnboardingStateMachine` | 集中管理状态、事件准入、检查点和能力操作顺序；不依赖 ViewModel、WPF、具体平台实现或容器 |
| `OnboardingViewModel` | 将状态机适配为命令、本地化文案和步骤条；不自行改变步骤、保存检查点或决定恢复路由 |
| `App` 组合根 | 创建和组装依赖，提供明确的运行时准备及开始识别入口，持有应用级共享实例的最终释放责任 |
| 词典、模型配置和目标选择模块 | 封装各自状态和操作；协调器读取就绪结果和稳定阶段，不自行处理文件、哈希、协议、指纹算法、HWND 身份或捕获清理 |

词典就绪后，通过现有组合根提供的明确准备入口只成功初始化一次识别运行时，然后向引导提供同一个模型配置和目标选择状态。协调器接受该操作入口及结果，不自行解析完整 `MainWindowViewModel`；首次识别也通过明确的能力入口请求，避免依赖识别页的按钮、控件和命令绑定。入口可以采用简单委托或现有模块方法，不为每个类新增接口或通用路由框架。

初始化期间显示本地化准备状态；失败有独立的重试反馈，不能显示无响应空页面。窗口跟踪和捕获在 UI 线程创建以绑定正确的 Dispatcher，重模型加载随后移到后台。正常关闭时先取消并等待在途准备、预览和配置操作结束清理，再释放容器及进程写入锁；清理只访问已经创建的实例，不能为了清理而解析尚未初始化的 OCR 或分词器服务。共享模型配置、目标状态及运行时由应用持有生命周期；页面离开时仅清理自身订阅和临时呈现；捕获取消和停止由发起操作的模块按所有权规则处理。协调器状态转换应可使用能力替身和委托测试，不创建 WPF 页面或真实 OCR / LLM。

替代方案：独立引导窗口会增加主窗口交接、主题订阅和 CLI 恢复判断；继续使用主界面遮罩会让用户看到不可操作的导航。使用单一宿主更贴合现有窗口模型。

### 2. 使用一个持久化检查点，实际就绪状态决定准入

通过 `ISettingsService` 保存字符串键 `OnboardingState`，取值为 `dictionary`、`model`、`window`、`completed`。前三项同时表示引导已经开始及恢复位置；第四步只驻留当前会话，仍保存 `window`，因为窗口句柄和截图不能跨进程恢复。写入保留其他设置；不新增文件和文件监听。

| 启动时状态 | 路由 |
|---|---|
| 无键，词典就绪且当前模型验证指纹匹配 | 作为已有可用安装迁移，写入 `completed` 后进入主界面 |
| 无键，未同时满足上述条件 | 先写入 `dictionary` 或 `model`，再显示对应引导；首次词典下载前必须已有检查点 |
| `dictionary` | 词典未就绪进入第一步，已经就绪进入第二步 |
| `model` | 词典未就绪回第一步，否则停在第二步，已有验证结果直接显示成功，用户点击下一步 |
| `window` | 词典未就绪回第一步；模型未验证回第二步；否则进入第三步重新选择窗口 |
| `completed` | 进入主界面；必要的词典修复是单独的启动准备状态，不重开四步 |
| 非空非法值 | 视为未完成并按实际条件恢复第一或第二步，不执行已有安装兼容迁移 |

词典就绪沿用实际选择的词典目录规则：默认缓存遵循安装元数据校验，显式 `KOTOBA_UNIDIC_DIR` 覆盖遵循既有覆盖校验；非法覆盖不通过下载默认词典来伪装修复。升级迁移只读取本地就绪信息，不发网络请求或自动开始识别。无验证指纹的历史配置进入第二步，保留所有字段并允许一次检测。

任何未完成检查点都优先于兼容迁移。这样在第二步经 CLI 配置成功后，虽然词典和模型都已就绪，重启仍回第二步，不跳过第三、第四步。

用户从第三步返回第二步时，先成功保存 `model`；从第四步返回第三步时，检查点保持 `window`。返回不清除已保存配置、已安装词典或当前会话中仍有效的目标与预览。保存失败保持原步骤并允许重试；第二步不提供用户主动返回第一步的入口，实际词典失效时仍按上述路由进入准备/修复状态。

替代方案：单纯的 `HasCompletedOnboarding` 布尔值不能区分旧安装与新用户的中途重启；持久化完整向导快照则会保存无效窗口和重复的就绪事实。有限检查点保留恢复意图，准入仍读取现有真实状态。

### 3. 词典步骤复用安装器并提供阶段反馈

第一步显示用途和一次性准备说明；缺失默认词典时沿用自动启动下载行为，在引导可见且检查点保存后发起。已有有效词典直接显示就绪。安装器报告稳定的阶段标识：下载、校验、解压、安装、就绪。只在下载且已知总量时显示百分比；未知长度或非下载阶段显示不定进度，安装完成事件才代表可以继续。

校验、解压及重文件操作不能阻塞 UI 消息循环；允许窗口移动、关闭和阶段重绘。失败停在当前步骤，显示本地化原因和重试；关闭时取消可取消的操作并清理临时资源。现有同步解压只能在阶段边界观察取消，不承诺立即中断已开始的解压。重试可以重新下载，不声称支持断点续传。

保留 `InstallFromArchiveAsync` 与目录覆盖能力，本次不增加离线导入按钮。已完成用户词典丢失时使用相同准备组件修复默认缓存，完成后返回主界面，保持 `completed`。

### 4. 模型步骤共用现有配置和验证契约

将模型配置区以共享视图承载在引导或设置页，按现有设置页提供三部分：AI 返回语言（释义语言）、Agent 辅助配置、手动配置。返回语言区域保留输入框、保存按钮、当前生效语言和保存/校验反馈；Agent 区域保留复制配置提示词入口；手动区域默认展开，保留协议顺序、密钥显隐、模型目录、错误详情和检测按钮。不把外观等其他设置页面内容带入引导。

连接部分绑定同一个 `LlmSettingsViewModel`；返回语言部分复用 `SettingsPageViewModel` 现有的语言保存行为和 `IExplanationLanguagePreferences`。共享区域不能仅绑定 `LlmSettingsViewModel` 而遗漏目前位于父级的语言属性与命令；具体采用共享组合视图或最小提取语言视图状态，避免复制校验和持久化规则。

返回语言沿用 `custom-translation-language` 契约：输入可以是任意合法语言名称，编辑草稿不立即生效，保存后才应用；留空保存表示跟随界面语言。该偏好与界面语言、Agent 配置提示词语言及连接四项字段分别控制，通过既有 `ExplanationLanguage` 键保存，返回语言变更不清除连接验证指纹，不要求重新检测模型，也不主动调用 OCR 或 LLM。没有 API Key 时仍可先保存语言；不填写自定义值不阻止后续步骤。

“下一步”要求当前配置完整、验证指纹匹配且没有在途检测或模型获取。只获取模型列表、保存字段或验证其他配置均不算通过。修改协议、地址、Key 或模型立即清除当前成功状态并阻止继续。点击继续时再次检查就绪状态，不使用步骤条上的旧完成标记作为凭据。

外部配置入口沿用当前提示词和 CLI 约定；引导状态在展示入口之前已持久化为 `model`，CLI 不读取或写入该键。重启后从最终配置恢复成功或未验证状态，并保留已保存的返回语言，仍由用户点击继续。未保存草稿沿用既有规则，不跨进程恢复。不自动重跑付费分析检查；沿用匹配的验证记录。

### 5. 目标选择共享状态，视图只有一个活动呈现者

从 `RecognitionPageViewModel` 最小提取聚焦的目标选择与预览模块，封装当前目标、代次、可用性、选择/重选、静态预览及预览捕获生命周期，沿用现有 picker、tracker、capture。引导和常规识别页组合使用同一个实例；引导不依赖包含识别、区域编辑、隐藏浮层和自动识别行为的完整 `RecognitionPageViewModel`。识别工作流和自动识别仍由原模块负责，不随本次提取扩大重构范围。

目标卡片的宿主隐藏/恢复、预览事件和飞入采用共享呈现逻辑，视图只处理呈现。当前静态预览以受限尺寸的 `CapturedFrame` 像素数据由共享选择状态持有，WPF 小图转换通过组合根注入委托，ViewModel 和预览事件不引用 WPF 类型。页面交接不能因为源视图卸载就清空它，也不能重新捕获来补图。应用最终释放共享模块；视图卸载仅取消自身动画并解除订阅，不释放共享目标状态或停止后来启动的识别捕获。

任一时刻只有可见目标卡片负责飞入和宿主恢复。隐藏的主界面不得同时订阅并播放动画。前进前要求当前目标有效且可捕获、没有在途拾取/预览；预览失败本身不等于目标失效，允许明确提示后继续，保持现有识别页语义。取消首次拾取留在第三步；取消重新选择保留仍有效的原目标。选择只获取预览，不调用 OCR、LLM 或自动识别。

第三步的“上一步”只返回第二步，第四步的“上一步”只返回第三步；再次进入选窗步骤沿用仍有效的选择和预览，不重复拾取或截图。未选目标或前进条件失效不妨碍返回；拾取、预览及清理尚在进行时暂禁用返回，防止跨页面操作冲突。返回不主动开始识别。模型或词典失效时阻止进入最终交接；第四步发现目标关闭或身份变化时返回第三步；暂时最小化时显示恢复/重选提示并禁用开始，恢复可捕获后可继续。

### 6. 第四步完成交接，不以识别成功为完成条件

显示所选模型和目标窗口摘要、返回第三步的入口和“开始识别”主操作。点击时防止重入，重新检查词典、模型验证、目标可用性及捕获空闲，确保运行时和主界面已准备好。先成功保存 `completed`，再在同一 UI 交接中切换到主界面并且仅通过明确的开始识别入口调用一次既有识别用例；协调器不获取识别页面或读取其命令绑定，不再次选择或捕获预览。完成交接期间禁用返回与重复开始。

保存失败留在第四步并提供重试，不发起识别、不报告完成。运行时准备失败同样不保存完成。完成后的识别异常、超时或无文字都由主界面现有反馈处理，不撤销完成状态。自动识别按已有偏好，仅由现有首次识别会话逻辑启动。

不要求设置持久化与进程崩溃间的分布式事务：如果保存完成后进程异常退出，下次直接打开主界面，由用户主动开始识别，不自动重放可能已经发出的云端请求。

### 7. 视觉、可访问性和验证

2026-10-31 用户确认交互 HTML 原型后，采用相同的简洁视觉并以原生 WPF 实现：留白双栏、大标题、细进度条、圆点步骤条和圆角主操作。保留 Windows 原生标题栏；不嵌入浏览器、不加入原型中的模拟数据、模拟失败或模拟识别结果。第一步右侧为词典说明插画，第三、第四步使用真实目标预览；完成仍直接交接现有主界面。

引导拥有局部 `OnboardingStyles.xaml`；颜色使用现有动态语义画刷，中英文文案继续放在 `.resx`。底部前进、返回和重试区位于内容滚动区域之外，900×620 窗口下仍可访问；长表单在内容区滚动。顶部主题和语言选择绑定现有共享偏好，不改变主界面设置的呈现。

模型页使用紧凑的 `OnboardingModelView`，手动配置和 AI 助手入口以原生 TabControl 切换；协议、密钥显隐、模型获取、连接检测、取消、错误复制及返回语言保存均调用现有共享状态和命令。两个模型编辑器共用密码同步与剪贴板交互，避免各自维护配置行为。目标视图只新增 `IsOnboarding` 呈现选项，改变预览比例和内部操作入口的可见性；选择、宿主隐藏恢复、飞入、缓存图片和清理所有权保持共享。

仅步骤改变时播放 240ms 淡入和 10px 位移，使用渲染变换，不在动画结束时推进业务步骤或发起请求。Windows 关闭客户端动画或启用高对比度时直接显示终态；视图卸载时移除动画时钟。词典和模型进度来自真实阶段，沿用已有选窗飞入；语言、主题和异步反馈刷新不重播切步动画。

引导外壳右上角始终显示界面语言选择器，以语言自身名称列出已有支持语言，直接绑定共享的 `Settings.Language` 偏好。四步、词典下载、运行时准备和错误重试期间均可切换；沿用现有即时本地化和保存机制，不另加语言状态、不重新创建页面或重放操作。后续主界面与设置页共享同一选择，独立保存的 AI 返回语言保持原有规则。

使用现有 Fluent 设计令牌、画刷、主题和本地化端口，显示四步名称、当前步骤和完成状态。步骤条仅展示进度，不提供额外跳转。第一步提供准备完成后的下一步；第二步只提供下一步，不显示或启用返回第一步的按钮和快捷操作；第三步提供返回第二步与下一步；第四步提供返回第三步与开始识别。返回不要求满足前进条件，但须等待在途选择/预览清理结束；自动修复路由不受手动返回按钮限制。操作进行时防止重复执行和跨步骤冲突，关闭按钮始终保留。切步后焦点进入当前标题或首个操作，加载和错误通过可访问状态播报。

所有新增用户文案放入英文和简体中文 `.resx`；状态保留稳定阶段/结果码后重新本地化。单元测试用设置 fake、安装/运行时/工作流委托和现有端口替身验证路由与副作用，避免真实大词典下载和供应商请求。WPF 手工验证动画、焦点、主题、窗口恢复和真实 GUI 重启。

### 8. 显式状态机与完整步骤视图

按用户确认的重构方向，唯一可写流程状态收敛为 `OnboardingState(Phase, Step, ErrorKey)`。`Phase` 明确区分未启动、准备中、准备失败、已完成用户修复中/修复失败、可操作、启动识别中、主界面和已关闭，不再组合 `_completed`、`_runtimeReady` 和可写 `IsBusy` 来推断处境。词典、模型与目标的真实就绪信息仍由现有能力快照提供，只作为事件准入条件，不重复保存。

| 当前阶段 / 事件 | 转换与效果 |
|---|---|
| 未启动或准备失败 / Initialize | 读取真实就绪状态和检查点，未完成安装先保存恢复位置再准备；已完成安装进入独立修复 |
| 准备成功 / 完成回调 | 未完成安装进入恢复位置的可操作步骤；已完成安装进入主界面；兼容迁移先保存完成标记 |
| 可操作 / Next | 显式匹配词典→模型、模型→选窗、选窗→确认及相应门禁；保存检查点成功后才切步，不对枚举加减 |
| 选窗或确认 / Back | 无目标操作在途时分别返回模型或选窗；准备失败阶段返回后仍可重试，不能因此解锁前进 |
| 最终确认 / Next | 再次刷新目标身份，先保存 `completed`，再进入启动中并切换主界面，只调用一次识别入口；识别失败也保留完成状态 |
| 可操作 / Refresh | 按原规则处理词典失效和目标关闭，保存失败保留当前步骤并阻止绕过准备门禁 |
| 任意阶段 / Dispose | 进入已关闭状态；拒绝新事件，不读取已释放服务，也不接受晚到异步结果 |

已经可操作时重复初始化直接忽略；准备失败及取消保留显式重试入口。ViewModel 只转发状态与本地化呈现，只有步骤实际改变才通知 `Step`，语言、主题和就绪反馈更新不会替换活动步骤或重播动画。

`OnboardingPage` 只保留主题/语言栏、数据驱动的步骤条、滚动承载区和底部操作。中间通过 `OnboardingStepTemplateSelector` 按一个步骤枚举装载四个完整视图之一，不再用 `IsDictionary`、`IsModel`、`IsWindow`、`IsReady` 拼接左右区域。各步骤拥有自己的详情和视觉，共用 `OnboardingStepLayout` 的双栏与标题；模型和目标继续使用同一个宿主 `Settings` / `Selection`。公共布局负责加载后聚焦标题，宿主负责滚动复位和渲染动画。视图卸载只清理临时呈现与订阅，不释放共享业务状态。

采用枚举、不可变快照和普通 C#，不引入状态机依赖、每步业务 ViewModel 或通用向导框架。新增架构测试固定流程模块与 WPF、ViewModel、平台实现及容器的依赖边界；回归覆盖显式阶段、重复事件、取消重试、完成后修复、关闭及晚到结果，并确认语言和主题更新保持同一活动视图实例。

## Risks / Trade-offs

- [隐藏宿主视图重复订阅，导致飞入播放两次或旧清理停止识别捕获] → 仅挂载活动页面，预览资源和代次采用单一所有者，专门测试交接与晚到回调。
- [词典未就绪时提前解析完整 DI 对象图] → 启动协调器不依赖识别 ViewModel，组合根提供一次性延迟初始化，退出不解析未创建服务。
- [解压耗时但 UI 误显示下载 100%] → 分阶段不定进度，重操作移出 UI 线程；不承诺不支持的解压中途取消或续传。
- [已有但未验证的老配置仍需一次引导] → 保留字段与词典，直接进入模型检测，完成后永久退出首次流程；没有可靠验证记录时不假定服务可用。
- [完成状态保存失败导致误开始或请求重复] → 保存成功前不调用识别，开始按钮防重入；保存后崩溃不自动重放请求。
- [匹配的验证指纹不能保证供应商永久可用] → 它只用于准备门禁和恢复，后续请求保留正常错误处理，临时故障不重开引导。

## Migration Plan

1. 新版本启动在已有进程写入锁内读取 `OnboardingState` 和本地准备状态。
2. 仅无键且词典、模型验证都就绪的安装迁移为 `completed`；其他安装保存有效检查点并进入对应步骤。
3. 不改写现有连接字段、词典缓存或其他偏好。回退旧版本时，通用设置服务保留未知的引导键；旧版本继续按原启动方式运行。
4. 合并前完成新用户、中途退出、CLI 恢复、老用户迁移、完成后修复五组验收。
