## Goals / Non-Goals

**Goals:**

- 保留同一个龙女仆、原始动作、表情变化和打赏弹窗风格。
- 左下角角色更大，默认约 300 DIP 高，并适配最小 900×620 窗口。
- 达到第 3／7 个实际使用日后，等下次启动再自动邀请支持，识别期间不打扰，已展示的节点不重复提醒。
- 所有素材随软件发布，状态只在本地保存。

**Non-Goals:**

- 不重做识别页、设置页和首次引导。
- 不增加桌面宠物窗口、网站版拖拽玩法、支付后台或支付验证。

## Decisions

### 1. 原素材转换后直接打包

从 `Clutch/Mascot/MascotA.heic` 和 `MascotB.heic` 导出透明 PNG 图片帧，保留原始分辨率、帧顺序和公共画布。已有网站素材记录两段均为 121 帧、24 fps；转换时读取并核对原文件的实际帧数。

转换脚本、帧数／尺寸／速度说明和生成结果放在当前仓库，普通构建直接使用生成结果。原始 HEIC 只用于开发时转换；不使用演示 GIF 代替角色动画，也不采用网站缩小至 320 像素高的图集作为主素材。

角色帧共用一个有上限的缓存，最多缓存 40 帧，避免常驻角色和弹窗各自加载完整动画。图片解码放到后台，界面只更新当前图片。

### 2. 在左侧栏底部安排角色和按钮

在 `MainContentView.xaml` 左侧栏中明确划分顶部导航和底部角色区域。角色默认约 300 DIP 高、等比例显示，咖啡按钮放在角色下方，底部留约 20 DIP；空间不足时缩小角色，保证导航和按钮都能操作。

沿用 Clutch 金色胶囊按钮及悬停颜色；确认支持后切换为淡绿色“我已支持”。识别页和设置页共用同一个常驻区域，首次引导期间不显示。

保留 Clutch 的隐藏调试操作，macOS 的 Option 在 Windows 对应 Alt。仅 Debug 构建中，按住 Alt 点击左下角“我已支持”／咖啡入口时，取消本次启动的待检查项，清除支持行为、打赏确认、最后提醒日期和节点；识别次数、活跃日和其他设置保持不变。保存成功后同步恢复金色按钮、未支持文案和角色鼠标互动，结束已有弹窗的庆祝并重新打开未支持状态弹窗，不消耗提醒节点，也不在本次运行恢复自动提醒。保存失败则保留原状态并反馈错误。Debug 入口提示补充 Alt 重置说明，Release 不显示提示，Alt 点击也只正常打开弹窗，不执行重置。

### 3. 按 Swift 桌面版还原动画

播放分为“跟随鼠标”“变开心”“跳跃庆祝”三个阶段。两个角色实例独立维护播放位置，共享图片缓存和支持状态。

| 效果 | 复刻规则 |
| --- | --- |
| 播放速度 | 原始 24 fps，以实际经过时间推进；单次时间增量最多 0.1 秒 |
| 常驻角色 | 鼠标靠近咖啡按钮时正放 A，远离时倒放 A；到端点后停留 |
| 弹窗角色 | 仅在弹窗右上角的 1/16 区域内，靠近关闭按钮时倒放 A；离开该区域就正放 A |
| 方向判断 | 按鼠标到按钮矩形的距离变化判断，累计变化达到 3 DIP 才换方向；窗口移动不算鼠标移动 |
| 呼吸 | 跟随鼠标时使用 `1 + sin(time * 2.2) * 0.006` 的纵向缩放，脚部固定 |
| 庆祝 | 先正放完 A，再循环 B；已确认支持时重新打开直接播放 B |

原版使用约 60 Hz 更新，这里用 WPF 渲染时钟驱动，同一帧不重复更换图片。界面卸载、主窗口最小化或常驻角色所在应用失去活动状态时暂停对应播放；弹窗单独按可见性管理。恢复时重置计时基准，关闭时释放订阅。Windows 关闭动画或启用高对比度时使用开心／感谢静帧。

### 5. 使用天数和提醒规则

在 `RecognitionPageViewModel` 现有成功返回处通知支持组件，不把支持功能放进 Core 识别流程。

- 手动识别成功返回一次记一次，包括首次引导交接后的识别；没有识别到文字的正常完成也算一次。
- 自动识别实际调用识别并成功返回一次也记一次，没有识别到文字的正常完成同样计数；纯采样、跳过、失败、取消和过期会话不计数。
- 日期取完成时的本地日期，同一天只计一个活跃日。不按安装天数、连续天数或后台运行时长计算。
- 有效使用只保存次数和日期，由已保存的活跃日及最后提醒节点确定待提醒资格，不安排识别后的弹窗；本次运行新达到的第 3／7 天节点只能在下次启动时检查。
- 每次进程启动时读取已保存的待提醒资格，主界面首次就绪后等待 3 秒，只检查一次。恢复最小化窗口、切换页面或重新获得焦点不算下次启动，不重新检查。
- 只在本地时间 `10:00 ≤ 时间 < 19:00`、引导已结束、没有支持弹窗、没有窗口／区域选择操作、前台应用非全屏时自动弹出。启动等待期间一旦开始手动识别、启用自动识别或进入窗口／区域选择，本次启动就放弃自动展示；自动识别的采样间隔也算正在使用识别功能。
- 条件不满足时保留待提醒资格，等下次启动再检查；本次运行中识别完成、停止自动识别、退出全屏或进入白天后都不补弹。实际展示前再次核对识别与选择状态，避免启动检查和识别开始同时发生时弹窗。
- 取启动时已达到且未提醒的最大节点（3 或 7）。自动展示前保存节点和日期；一天最多自动展示一次，跳过的旧节点不补弹。第 7 个节点展示后不再自动邀请，未展示的第 7 个节点可以留到后续启动展示。
- 成功打开 GitHub 或确认支持后永久停止自动邀请，只有显式调试重置可恢复资格。手动打开不受时间和节点限制，不消耗提醒节点。

使用现有 `ISettingsService` 的一个独立字符串键 `SupportState` 保存 JSON，包含版本、累计次数、去重日期（最多保留 30 个）、最后提醒日期／节点、是否已有支持行为、是否已确认打赏。支持组件统一更新这份状态，保存成功后才发布变更。缺失或损坏时使用默认值；写入失败只提示／记录支持功能错误，不影响识别，也不宣称确认已保存。提醒记录保存失败时本次不自动弹出。

### 6. 保持实现集中

在 App 的 `Support` 下集中放置状态、提醒协调和动画控制，视图放在 `Views/Support`，复用角色控件。`MainWindowViewModel` 持有支持入口，应用组装时接入共享设置与生命周期。只有鼠标坐标、前台全屏判断和窗口定位需要少量 Windows 适配；不新增通用框架或修改 Core 分层。

新增界面文案进入现有英文、简体中文 `.resx`。代码、注释、测试名和日志继续使用英文。

## Risks / Trade-offs

- Windows 与 macOS 的字体和材质不同 → 对照原版比例、颜色、间距和交互做 WPF 还原，优先验收用户看见的效果。
- 放大动画可能增加内存和界面负担 → 保留有上限的共享缓存，隐藏时暂停，避免同步解码卡住识别界面。
- 自动提醒可能打断识别 → 识别只记录使用，自动展示仅限下次启动的一次检查；开始识别即取消本次自动展示，节点先保存再展示。

## Migration Plan

只新增素材、组件和 `SupportState` 设置。已有用户从 0 个记录日开始，不猜测过去使用天数。回退应用版本时，旧版本按现有设置规则保留未知字段。
