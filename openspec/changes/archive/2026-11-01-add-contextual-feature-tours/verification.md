## 已覆盖的行为

- 主界面按四步推进，最后一步才保存完成记录；完成后重新创建会话不再提示。
- 两组完成记录独立，不覆盖主题等其他设置；无效记录按未完成处理。
- 中途退出后从第一步重新开始；保存失败只结束本次会话，下次启动仍可提示。
- 主界面气泡鼠标确认和回车确认不触发底层操作，结束后恢复正常输入。
- 区域说明期间无法真正确认选区；最后一步只结束说明，仍需用户点击原有确认按钮才保存选区。
- 区域选择器暂时隐藏后继续原步骤；目标失效后重新进入从第一步开始；被动红框不触发引导。
- 切换文案不改变进度；释放展示适配器后取消流程与文化订阅。
- 流程模块不得依赖 WPF、Platform.Windows、页面、视图模型或依赖注入容器，原有依赖方向继续受架构测试约束。

## 界面检查

独立桌面验证使用真实主界面视图和真实区域选择窗口，生成并检查了 80 张预览，覆盖：

- 中文、英文，浅色、深色主题。
- 主窗口对应 900×620 和 1100×800 的内容尺寸，四步控件滚动与气泡定位。
- 区域选择器的黄色角说明和确认按钮说明，包括黄色角贴着左上边界。
- 100% 和 150% 的渲染比例。
- 36×80、84×100、300×140 的小视口：不会因箭头定位崩溃，结束按钮保持在窗口内。极小视口空间不足时优先保留结束操作。

还增加了“区域气泡不得盖住真实确认按钮”的断言。气泡采用不透明主题背景，避免底层文字透过气泡影响阅读。

预览位于测试输出目录的 `previews/guidance/`。本次未在不同 DPI 的物理显示器之间实际拖动窗口；跨屏跟随继续复用已有机制，渲染比例检查不能代替多显示器实机检查。

## 审查与测试隔离

独立代码审查发现并修复了小目标窗口下的定位异常，最终复审没有新的 P1/P2 问题。

测试过程中遇到过已有支持窗口焦点测试不稳定，以及全局主题样式影响另一个测试窗口透明度的问题。已通过独立 HEAD 基线比较核实焦点问题，给共用光效测试宿主显式设置 `Style = null`，并将新增桌面检查放入不抢焦点的屏幕外子进程。最终 App 全量重跑通过，未修改生产窗口样式。

## 重跑方式

```powershell
dotnet build KotobaSenpai.slnx --no-restore
dotnet test tests/KotobaSenpai.App.Tests --no-build --no-restore
dotnet test tests/KotobaSenpai.Platform.Windows.Tests --no-build --no-restore

dotnet test tests/KotobaSenpai.Architecture.Tests --no-build --no-restore

```
