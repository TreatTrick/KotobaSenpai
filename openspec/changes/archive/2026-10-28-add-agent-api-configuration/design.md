## 背景

当前应用已经有三种协议实现：`OpenAiChatCompletionsProtocol`、`OpenAiResponsesProtocol` 和 `AnthropicMessagesProtocol`，并通过 `LlmProtocolRegistry`、`LlmEndpointHelper`、`HttpLlmModelCatalog`、`LlmPhraseAnalyzer`、`PhrasePromptBuilder` 和现有解析校验器完成请求。新功能应复用这些实现。

`LlmSettingsViewModel` 目前逐字段即时写入；`SettingsService` 在构造时载入 JSON 并缓存，缺少整体配置快照和批量提交。让 CLI 在 GUI 运行时直接改文件会造成状态不同步，后续写入还可能覆盖修改。首版通过正常退出 GUI、CLI 本进程独占配置和重新打开界面解决，不增加跨进程热更新。

语言服务已经支持 `zh-CN` 与 `en`，切换时发布文化变更通知。主窗口的识别初始化会加载 OCR 和词典，配置工具必须避开这条重型启动路径。

用户已明确选择继续在 JSON 中保存密钥。参考仓库 `C:/Users/11541/Downloads/cc-switch` 的 `src-tauri/src/config.rs` 提供 JSON 原子写入，`codex_config.rs` 使用 JSON 写入凭据；这里只参考文件持久化方式，不复用其外部应用配置管理逻辑。

## 目标与非目标

**目标：**

- 用户把 API 资料和密钥交给本机外部 Agent，即可检测、验证并启用配置，不需要选择协议。
- 云端分析是识别的必需流程，不提供禁用开关或独立本地模式；连接配置仅包含协议、地址、Key 和模型，历史启用键不再影响运行。
- 协议按 Responses、Anthropic、Chat Completions 的优先级检测；用户未指定模型时，由外部 Agent 从实际返回的模型中自行选择便宜、响应快且适合任务的候选。
- 复制的提示词与用户当前选定的应用语言一致，具备语义等价的中英文版本。
- 缺少 Key、只有官网、无法浏览文档、模型不明确、协议不支持和各种请求失败，都有明确且有限的恢复路径。
- CLI、设置页和正式识别共用协议与请求实现；候选验证不污染当前配置。
- CLI 写入前正常退出已运行的应用，结束后恢复原先打开的 UI；成功后整体保存，失败不产生半套配置。

**非目标：**

- 不实现 MCP、内置聊天 Agent、远程配置服务器或新的供应商协议。
- 不实现常驻配置宿主、命名管道服务、跨进程进度推送或配置热更新；不启动 App 执行配置，也不自动强杀 UI。
- 不读取或修改 Codex、Claude Code、Cursor 的账号文件，不从其他软件借用密钥。
- 不引入 DPAPI、凭据库、加密迁移、完整配置历史或多供应商档案管理。
- 不要求用户额外安装 Node、Python 或手工配置 PATH，也不把协议判断完全交给外部 Agent。

## 设计决策

### 1. 提示词由应用按当前语言生成

在现有 LLM 设置区增加“让 AI 帮我配置”卡片，提供复制提示词入口，说明外部工具写入配置时应用会暂时退出并在结束后自动重新打开。设置页自己发起的检测在本页显示进度；外部 CLI 操作由 Agent 报告进度和结果，不向已关闭的界面推送。沿用现有 Fluent 卡片、字体、间距与深浅主题资源，不新增主导航标签。高级手动配置默认展开，顶部左侧提供“检测配置是否可用”按钮，仅按当前选定协议执行真实日语分析检查，不自动切换协议，不改写地址字段，也不回填或应用连接字段，仅更新验证状态。检测时按钮内显示旋转等待环并禁止重复点击，完成或取消后恢复原图标；右侧成功时显示绿色圆圈勾和“下方配置可以使用”，失败时显示红色三角感叹号和“配置不可用”，下方展示本地化原因及脱敏技术详情，最右侧提供“复制错误信息”按钮。剪贴板反馈与验证状态分别保存，复制提示词或错误信息不会覆盖验证结果。

提示词放入现有 `.resx` 本地化资源，直接跟随应用当前显示语言选择完整中文或英文版本，不额外维护语言资源键或插入语言代码。复制时重新生成，切换语言后不沿用旧语言缓存；无可匹配文化时使用现有英文回退。自动填入当前安装目录中的 CLI 绝对路径、接口版本和完整的能力查询命令，不填入现有密钥或其他私有配置；Agent 按提示词本身的语言回复。能力查询使用 Windows PowerShell 调用形式 `& '<CLI 绝对路径>' capabilities --json`，由软件对路径中的单引号进行双写转义，处理空格及其他特殊字符；实际复制结果必须是可执行的完整命令，不保留路径占位符，也不依赖 PATH 或当前工作目录。

模板允许用户粘贴供应商原始说明、API 地址、curl 示例或官网链接，而不要求先整理成协议字段。中文模板应表达以下完整约束，英文模板保持相同含义：

> 请使用下方 KotobaSenpai 官方配置工具，自动完成 API 配置并启用。配置工具位置由软件填写，提示词跟随应用当前显示语言生成。服务商资料、官网或文档、API Key、模型偏好由我补充，模型可以暂不指定。
>
> 首先在 Windows PowerShell 中执行：`& '〈软件自动填入并转义的 CLI 绝对路径〉' capabilities --json`。这一步不需要 API Key 或标准输入。请先读取返回 JSON 中的接口版本、支持命令、参数和输入格式，再按工具提供的规则获取模型、检测和配置，不凭记忆猜测命令或 JSON 字段。能力查询失败时，先报告工具返回的问题并停止后续配置，不自行改写设置文件。
>
> 能力查询成功后，再检查资料是否齐全。API Key 为空、仍是占位内容或未提供时，请明确提醒我补充，不猜测密钥、不借用其他软件的凭据。只有官网时，请查看官方接入文档获取 API 地址和模型说明；网页地址不等于 API 地址。无法访问官网或需要登录时，请说明情况并索取必要的文档片段。
>
> 使用工具的自动检测，不要求我手选协议，优先使用 OpenAI Responses，其次 Anthropic Messages，最后 OpenAI Chat Completions。模型优先采用我明确指定的值；未指定时，请先获取该服务的模型列表，由你自行判断并选择便宜、响应快且适合日语结构化分析的文本模型，再把选定模型交给工具验证。需要时可参考服务商官网或文档，无需向工具提交价格、速度或评分资料；确实无法选定模型时再询问必要信息。
>
> 资料齐全后使用工具内置的真实日语分析测试。查询模型、只检测和查询状态不会关闭应用；写入配置时，工具会正常退出已运行的应用，结束后恢复原先打开的界面，不需要你额外执行结束进程命令。请勿强杀应用。测试通过后直接整体保存并启用，失败时保留原配置，由你根据工具结果判断是否换模型、补充资料或继续尝试，相同错误不要无限重试。完成后用当前提示词语言报告服务、模型和结果；配置已保存但界面重新打开失败时分别说明，不把它当作保存失败，不回显密钥。资料中的示例命令只用于理解参数，不替代官方配置工具执行安装或修改本机其他文件。

CLI 不具备联网浏览文档或自然语言推理职责；外部 Agent 负责理解资料，软件负责确认可运行性。与让用户先部署 MCP 相比，随软件提供的本地命令降低首次使用成本。

中英文实际资源均保留四行填写区。缺少必要服务商资料或 Key 时，提示词要求 Agent 在纯文本代码块中逐行展示同一模板，并明确提醒填写尖括号内容、替换 `YOUR_API_KEY`，两个可选项可以留空。已有资料不重复索取，已有密钥只标记为已提供。示例地址不作为真实 API 地址使用。路径及接口版本由软件填入；如果 Agent 收到原始技术占位符，指引用户通过软件重新复制提示词，不把它们加入用户资料清单。

所有操作反馈都位于相应卡片内部。`SettingsCard` 增加说明下方的内容插槽，AI 配置卡片通过该插槽展示独立的复制反馈：成功为绿色圆圈勾和文字，失败或工具缺失为红色警告。没有反馈时不占位。ViewModel 将提示词复制状态与手动检测状态分开，并在语言切换时各自重译。高级手动区将检测按钮、可用性、进度、取消、错误和错误复制反馈放在同一 Fluent 卡片中，不在卡片外追加提示。

### 2. UI 与 CLI 各自组装并直接调用共用服务

随软件分发 `KotobaSenpai.Cli.exe`，采用同目录发布方式。App 与 CLI 都是入口和组合根，各自在本进程组装 Core 配置用例与 Platform.Windows 基础设施。CLI 不启动 App 来执行配置，不创建 WPF Application，不初始化 OCR、UniDic、JMdict、窗口捕获或词典下载。App 删除配置专用启动参数和标准输入输出转发，只保留普通 GUI 启动。

```text
外部 Agent ── 本地 CLI ──┐
                         ├─ Core 共用配置用例
设置页 ──────────────────┘       ├─ Platform.Windows 协议、请求与真实分析验证
                                  └─ Platform.Windows 设置服务原子提交
正式识别 ────────────────────────同一套协议与请求执行层

CLI 写入：检查资料 → 正常退出已有 GUI → 取得互斥 → 加载最新设置
          → 本进程验证并保存 → 释放互斥 → 恢复原先打开的 GUI
```

`SettingsService` 的唯一文件存储实现移到 `Platform.Windows/Settings`，Core 保留 `ISettingsService` 端口，UI 与 CLI 共用同一个实现，不各写一套 JSON 存储。供应商分析提示词由基础设施中的同一个 `PhrasePromptBuilder` 生成，按自定义释义语言功能使用固定英文指令和请求携带的目标语言，不再保留旧的中英文分析资源或额外本地化适配。UI 专属文案与中英文 Agent 配置提示词仍在 App，跟随界面语言；相同分析请求和目标语言产生等价业务请求。

`capabilities`、`llm models`、`llm detect` 和 `llm status` 不关闭或重启 GUI。能力查询不加载设置，其他只读命令仅创建只读设置快照，不保存或保留用于后续写入的缓存，不通过语言或日志初始化产生写入。CLI 自己输出一个最终 JSON，不建立配置子进程通信、就绪握手、内部协议版本协商或取消转发。

`llm configure` 完成静态输入校验后，仅请求当前 Windows 用户、与本次安装路径匹配的 GUI 正常退出，最长等待 10 秒。退出失败返回 `app_busy`，不强杀、不执行配置；原本未打开时不主动打开界面。生命周期适配只负责 GUI 关闭、恢复和写入所有权，配置用例作为回调在 CLI 进程执行。

GUI 在创建可写设置实例前取得按 Windows 用户区分的命名互斥，持有到退出；CLI 在正常关闭 GUI 后实际取得同一互斥，再加载最新设置，并持有到配置操作结束。未取得的一方返回忙碌，不排队或使用旧缓存。命名 Mutex 由同一线程取得和释放；CLI 的异步配置在持有互斥的专用线程范围内执行，防止异步续体切换线程导致释放失败。只读命令不取得写入所有权。

配置成功、失败或取消后，待本进程操作结束并释放互斥，再恢复本次关闭的 GUI；已有 GUI 成功启动时不重复创建。恢复等待有界，失败独立返回 `uiRestore` 警告。已提交仍报告成功，不回滚或重复保存。未预期异常导致无法确认提交时，`applied` 为空，要求先查询状态。配置期间仍会中断识别，不新增常驻服务、命名管道或跨进程热更新。

### 3. 使用明确、可恢复的 JSON 命令契约

| 命令 | 职责 |
| --- | --- |
| `capabilities --json` | 无需 Key、配置输入或预先获知接口版本即可调用，返回接口版本、支持的协议、各命令调用方式、输入字段及必填规则和实际安装路径 |
| `llm models --stdin --json` | 自动选择候选认证方式获取模型，明确区分目录不可用与密钥失败 |
| `llm detect --stdin --json` | 自动检测并执行真实业务验证，不保存、不启用 |
| `llm configure --stdin --json` | 正常退出已有 GUI，在 CLI 本进程检测、验证并整体保存，结束后恢复原先打开的 UI |
| `llm status --json` | 只读查询脱敏配置可用性，不查询常驻操作进度 |

输入包含 `schemaVersion`，以及按命令需要的 `endpoint`、`apiKey`、`model`、可选 `websiteUrl`、`language` 和 `protocolHint`。协议提示不是必填项，不能代替验证或把低优先协议提前。模型发现不要求模型参数；检测与配置使用用户指定或 Agent 选定的 `model`，不要求价格、速度、评分或选择证据字段。CLI 不负责浏览网页或判断哪个模型更经济。所有命令均不在终端等待用户逐项回答；Agent 根据工具结果自行选模，必要时向用户补问。

标准输出只写一个完整 JSON 结果；CLI 直接序列化共用用例的结果，诊断走标准错误且不包含密钥。结果统一包含接口版本、操作标识、状态、稳定错误码、待补字段、可选模型候选、下一步建议和脱敏后的已解析配置。涉及写入的结果另含 `applied` 和 `uiRestore`，区分是否已提交与界面恢复状态：`applied` 为真表示已完成提交，为假表示确认未提交，为空表示无法确认；未确认时不当作已知失败反复重试。CLI 的程序诊断与错误文本保持英文，设置页通过错误码本地化，外部 Agent 按提示词语言向用户解释；CLI 不向原 GUI 推送进度。

退出码固定为：`0` 成功，`2` 输入或待补资料，`3` 供应商或检测失败，`4` 并发冲突或忙碌，`5` 存储、恢复启动或安装错误，`130` 取消。已提交而仅 UI 恢复失败时返回 `0` 并附警告，不误报保存失败。输入 JSON 错误、版本不支持和空输入不发起供应商请求，也不关闭 GUI。检测与配置支持取消；标准输入、GUI 退出与恢复等待均有超时，不无限等待。取消以提交时点区分：尚未提交时不保存，已完成原子提交时如实返回已应用，不能返回暗示配置未变的取消结果。

### 4. 自动检测必须与正式请求共用实现

Core 增加不可变的候选配置、检测结果和配置用例契约。Platform.Windows 整理现有 `LlmPhraseAnalyzer` 的执行部分，使其接收显式配置快照；正式识别由现有设置适配读取快照后调用，检测由候选快照调用。两者复用同一 `ILlmProtocol`、认证、地址候选、请求构造、HTTP 执行和响应提取。

模型发现继续使用 `ILlmModelCatalog` 与现有目录解析。检测器仅编排候选和判定结果，不自行构造 Bearer、`x-api-key`、`messages`、`input` 或工具调用的另一套实现。共用配置服务提供两个有明确区别的入口：UI 调用 `CheckCurrentAsync` 检查已保存的四项配置，检测器 `CheckAsync` 使用当前协议和正式分析流程，不切换协议；CLI 的 `llm configure` 继续自动检测并保存。两条路径复用同一个实际分析器、测试样本、结果校验和错误映射。

仅检测注册表已有的三个协议。默认自动检测按固定优先级 `openai-responses`、`anthropic`、`openai-chat` 检测可用候选；只有前序协议不适用或验证不通过后才回退。完整地址和文档提示用于匹配、补齐各协议的候选地址与解释适用性，不把后序协议提前。多个协议同时可用时选择优先级最高的协议。目录认证成功只能确认认证方式和模型，不能区分 Chat 与 Responses。成功判断要求实际分析响应通过现有解析和语义校验，不以 HTTP 200 或模型列表作为最终成功依据。

模型选择由外部 Agent 负责：用户明确指定模型时优先使用该模型；未指定时，Agent 先获取当前服务实际返回的模型列表，自行综合判断便宜、响应快且适合日语结构化分析的文本模型，必要时参考服务商资料。Agent 把选定的模型 ID 传给检测与配置命令，软件只验证该模型能否完成真实分析，不内置费用公式、速度排名或模型评分。目录不可用时，仍可验证用户或 Agent 根据接入资料明确提供的模型。

模型目录缺少价格或速度字段不构成工具错误，不要求补齐选择证据才允许验证。检测或配置缺少 `model` 时返回 `missing_model` 和 `input_required`，由 Agent 选定后继续；UI 内部操作使用用户填写或从目录选择的模型。软件不擅自改用列表首项，也不为选模遍历全部模型测速。

检测采用固定的短日语样例和稳定分词片段，不读取用户屏幕，不依赖本地 OCR 或词典安装；结果至少包含一个有效词条或短语。相同协议、方法、地址和模型的尝试去重，目录查询按认证方式去重。保留自定义路径前缀与查询参数，继续使用现有地址候选规则。

协议检测只按既定优先级验证有限的协议和地址候选，沿用共用 HTTP 执行层现有的请求超时与取消机制，不额外引入固定总时限、总请求次数或模型排名预算。选定模型验证成功后立即停止；失败时返回具体结果，由 Agent 自行判断是否换模型、补充资料或再次调用工具。软件不计算费用或速度预测，也不自动按模型排名继续试用。

正式识别原有“仅 404/405 切换地址”规则保持不变；检测器可在某个协议失败后尝试下一个协议，二者属于不同层级。检测的失败处理如下：

| 情况 | 行为 |
| --- | --- |
| 缺少 Key、地址或模型 | 返回 `input_required` 与具体字段，不保存；在补齐之前不发业务验证请求，也不关闭 GUI |
| 只有官网 | Agent 查文档补齐 API 地址；CLI 不把官网根地址自动当作 API 地址 |
| 用户没有模型偏好 | Agent 获取模型列表后自行选择便宜、响应快且适合任务的候选，向工具传入模型 ID |
| 目录没有价格或速度信息 | Agent 自行判断，工具不以缺少价格或速度证据为由拒绝验证 |
| 目录 404/405，但已明确提供模型 | 继续真实分析验证，不把目录缺失等同于服务不可用 |
| 404/405、协议请求不兼容或响应不满足结构 | 按既定顺序继续下一个尚未验证的协议或地址候选 |
| 401/403 | 记录该候选失败，允许其他尚未验证的协议、地址或认证组合继续；不重复相同组合，不能因 Chat 路径被拒绝就排除同用 Bearer 的 Responses。全部已尝试候选均被拒绝时报告认证或权限失败 |
| 429、5xx、网络失败、超时 | 停止当前操作并返回具体分类，不通过无界切换协议掩盖服务故障 |
| HTTP 200 但返回 HTML、非 JSON 或无有效分析结果 | 不保存，报告响应不兼容或继续下一个有依据的协议候选 |
| 需要新增原生协议或专用认证 | 明确报告不支持，Agent 可询问服务商是否提供现有兼容接口 |

候选请求仅向用户提供或 Agent 从其服务文档确认的 API 地址发送，文档链接只作为资料，不携带密钥；不跟随携带凭据的跨来源跳转。日志只保留分类和脱敏诊断。

### 5. 原子配置快照与重启读取

通过现有 `ISettingsService` 增加领域类型无关的字符串键值批量读取和条件批量写入。条件提交在同一锁内比较指定键的预期值，再写入完整新文件；先写同目录临时文件并原子替换，成功后才发布新内存状态。单键保存也使用同一原子持久化路径，避免只读命令观察到半份 JSON。写入失败不修改原文件或内存，未知字段始终保留。本变更不增加通用设置变更事件或跨进程文件监听。

Core 中的 LLM 配置适配把四个现有键作为一个不可变快照读取：`LlmProtocol`、`LlmEndpoint`、`LlmApiKey`、`LlmModel`。CLI 在取得互斥后才加载最新设置并记录快照；检测期间持有进程写入所有权，但网络请求不持有内存设置锁。UI 自己发起的检测仍在 GUI 进程内使用同一用例，验证期间改变语言或主题不阻止提交；修改 LLM 字段会取消检测并忽略旧结果，条件提交仍以 `conflict` 防止覆盖较新的设置。

成功后一次提交解析出的具体协议、实际可用地址、模型、密钥，以及四项配置的 SHA-256 验证指纹 `LlmVerifiedConfiguration`。指纹不包含明文密钥，仅用于把成功状态与同一份配置关联，不代表持续在线检测，也不新增加密存储方案。状态读取原子快照并比较指纹：匹配时为已验证，未匹配或历史配置没有指纹时不显示成功。对当前相同地址、密钥和模型重新配置检测失败时，以条件更新清除旧指纹；不同候选失败、只读检测失败或取消不清除原配置的有效验证状态。

只持久化具体协议，不把 `auto` 写入现有协议键。CLI 路径通过重新打开 GUI 读取最终配置，无需热更新。UI 手动检测仅以条件更新记录或清除验证指纹，不修改、回填或重新应用四项连接字段；手动编辑即时保存并清除页面旧提示，已经执行的正式识别请求继续使用开始时的完整快照。当前配置的检查结果不会因为另一个可用协议而显示成功。

配置只保存当前连接，不保留历史版本，不生成或读取撤销元数据。历史记录作为无关字段保留，不参与配置冲突检查。UI 和 CLI 均不提供撤销入口。

这保留 JSON 明文密钥方案。生成提示词不自动读取旧 Key，状态返回 `keyConfigured` 与 `verified`，不返回 Key 或指纹；检测失败可返回脱敏的 `errorDetail`，界面和复制内容再次隐藏密钥。输入解析错误、异常、HTTP 回显和工具输出均不回显密钥；不添加新的密钥确认或加密步骤。

## 风险与取舍

- 外部 Agent 不具备本机命令权限或联网浏览能力 → 提示词明确说明能力缺口，要求提供文档片段或使用有本机执行能力的模式，不声称仅靠对话即可配置。
- 接口名称和 Key 前缀不能可靠判断协议 → 保持 Responses、Anthropic、Chat 的优先级，用地址和文档匹配候选，再用同一业务请求验证；某一接口的认证失败不直接证明其他协议或路径不可用。
- 便宜和快速的取舍依赖实际服务与模型 → 交由 Agent 综合判断，软件验证选定模型的真实分析能力，不维护价格速度排名或要求用户填写评分资料。
- 检测可能产生实际 API 调用 → 使用固定短样例、有限协议地址候选和现有请求超时，失败反馈给 Agent 判断下一步，不扫描全部模型，不使用用户识别内容。
- CLI 配置会打断当前识别 → 提示词和设置卡片提前说明，正常退出时执行现有清理，结束后仅恢复原先已打开的 GUI，不恢复过期识别会话。
- UI 内部检测期间字段被改动 → 使用相关键的条件提交；CLI 通过退出 GUI 和进程互斥消除跨进程同时写入。
- 正常退出、配置启动或重新打开 UI 失败 → 有界等待，失败保留已知配置状态，恢复失败独立报告，不强杀或重复保存；状态未确认时先查询再决策。
- 多进程直接写配置会破坏内存一致性 → GUI 与 CLI 共用互斥，基础设施设置服务保持唯一文件访问实现，不允许两个入口同时持有可写缓存。
- 为配置工具引入重型启动依赖会降低首次成功率 → CLI 直接调用共享服务，不启动 WPF 应用，并验证缺少 App 可执行文件或模型文件时的能力查询。
- JSON 包含用户授权保存的密钥 → 保持既定存储方式，继续限制正常输出与日志回显，不扩展为加密专项。

## 迁移与回退

1. 先补设置原子快照和公共请求执行契约，保留现有设置键与正式识别行为。
2. 增加共用检测、验证与应用用例，将设置存储与业务提示词移到基础设施，再接入 CLI 本进程执行、写入互斥和正常退出与恢复流程。
3. 最后增加中英文提示词、Fluent 入口和打包校验。只有实际存在可调用的 CLI 时才允许复制包含路径的提示词。
4. 老用户无需迁移密钥或重填配置；已有高级手动配置继续工作，默认展开高级字段。
5. 失败不切换当前配置，成功只保存当前连接。旧记录不再用于恢复历史配置，未知字段仍由设置服务保留。

## 待确认事项

当前没有阻塞实施的问题。CLI 命令名、存储方式和首版协议范围以本设计为准；模型取舍和失败后的下一步由 Agent 判断，实际供应商兼容性以运行时验证结果为准，不预先承诺所有网站或模型均可自动接入。
