## Context

应用已经把识别出的日文分成若干句段，每段各发一次 AI 请求，取得词义和语法组合。相同原文、相同释义语言的成功结果可以在内存里复用。

详情弹窗目前只接收单词或短语的内容，没有整句原文和译文。单词本身已有所属句段信息；短语展示数据也需要保留这份关联。不能只凭词面查找整句，因为同一个词会在不同句子中重复出现。

用户已明确：整句译文按钮放在详情弹窗最上方；PhraseOverlay 详情弹窗不使用 FluentLight 光效。这里的 PhraseOverlay 指单词和短语共用的详情弹窗，当前代码中对应 `PhrasePopup`。

整句翻译另有独立设置开关。它同时控制后续是否生成译文和当前是否显示译文入口，不影响现有必需的词义、语法分析。

## Goals / Non-Goals

**目标：**

- 用户卡住时，可以在当前详情弹窗里点击查看对应原文和一份参考译文。
- 默认隐藏译文，继续以原文、查词和语法为主要阅读方式。
- 用户可以在设置中关闭整句翻译，关闭后不显示入口，后续分析也不生成译文。
- 复用现有分析、语言设置、模型配置和内存缓存。
- 同词不同句、跨行台词、换句和旧请求晚到时，都不会显示错配的译文。

**本次不做：**

- 自动双语字幕、翻译快捷键、单独的翻译窗口。
- 历史台词上下文、多版本翻译、精修和专用翻译模型。
- 新的断句算法、长期翻译记录、额外自动重试。
- 调整现有词义的匹配方式；这里只补全整句译文自己的位置关联。

## Decisions

### 1. 随分析生成，点击后展示

整句翻译开关开启时，每次现有句段分析同时生成一份译文。弹窗默认折叠，点击时读取已经保存的内容，不再发请求。没有取得译文时，点击显示无译文提示。关闭时继续原有词义和语法分析，不要求生成译文，也不显示顶部译文按钮。

考虑过点击后单独请求翻译：不用翻译的句子可以省去输出，但用户每次卡住都要等待一次网络请求，还要增加等待、取消和重试状态。首版采用一起生成，接受增加的输出量，并在交付前记录实际耗时变化。

### 2. “整句”沿用当前分析范围

直接使用现有 `SentenceSegmenter` 划出的句段，以及该请求的 `SegmentText`。一段可以跨多行；现有规则把同一行的多个短句放在同一段时，一起翻译。界面展开后显示实际原文，让用户清楚正在看哪一段。

不重新按每个句号切分，也不把整个识别区域拼成一篇译文。这样词义、语法和翻译共享同一份原文，跨行处理也保持一致。

### 3. 模型结果增加一个字段

每次构建句段请求时读取一次整句翻译开关，保存为本次请求的 `IncludeSentenceTranslation`。开启时，结果在 `groups`、`words` 之外增加 `translation` 字符串；关闭时保留原有两组数组，不要求或声明译文字段。三种协议的提示、结构声明和示例使用同一份开关值。开启时的指令要求自然、忠实地翻译整段，使用本次请求的释义语言，保留否定、条件等关系，不凭空补充人物姓名或情节。

模型不需要回传原文、句段编号或坐标。原文和所属句段由本地程序补上，避免模型抄错原文后造成关联错误。

请求要求返回该字段，模型无法翻译时返回空字符串；接收结果时允许字段缺失、空白或类型错误，统一当作无译文。去掉两端空白后超过 4000 字符的译文也视为无效，保留完整有效词义和语法，不截取一半冒充完整译文。整个响应不是合法 JSON 时，继续使用现有整次分析失败处理。

以上译文要求只用于开启的请求。关闭的请求即使被模型额外附上译文，也直接忽略，不把它当作缺失或失败，不增加重试。

只做文字格式和长度检查，不声称程序可以证明翻译正确或语言准确。译文按普通文字展示，不执行其中的链接或格式指令。

### 4. 用当前句段关联译文

每份可展示的句段结果保存当前句段标识、请求原文、请求使用的语言，以及可用译文。分析汇总结果和 `WordOverlaySession` 都携带这些数据。

- 单词入口根据当前命中的 `GroupedWord.SegmentId` 找译文。
- 短语入口根据该短语所属分析请求的句段找译文。现有短语只引用同一段内的词元，可以在构建展示数据时保留所属句段。
- 找不到对应句段时显示无译文提示，不能改用同词面、相似句子或上一条结果。

缓存按原文、请求语言和本次是否要求译文这三项匹配，继续共用现有容量上限。这样不会把关闭时没有译文的结果当作开启后的完整结果。缓存保存的译文不绑定旧画面的行号、位置或展开状态；命中后，使用本轮请求的句段标识重新建立关联。已有词元位置重绑定流程继续保留。

### 5. 展开是当前弹窗的临时状态

在弹窗第一行放置“查看整句译文”按钮，位于词头、读音、词义和语法之前。用户打开弹窗就能找到入口，不需要滚到内容末尾。点击后，原文和译文紧接在按钮下方展开，现有查词内容排在后面：

这一入口只在整句翻译设置开启时显示，关闭时整行译文入口和展开内容都不占位置。

```text
[查看整句译文]
词头、读音、词义和语法

       点击后
[收起整句译文]
原文：彼が来ないことには、始められない。
AI 参考译文：他不来，就没法开始。

词头、读音、词义和语法
```

没有译文时，展开区使用“暂无整句译文，可重新识别后再试”等本地化文案，不增加单独重试按钮。

内容数据继续使用只读 ViewModel。折叠状态由弹窗内的展开控件管理，不为一次点击引入新的状态框架。保留当前悬停目标时不重复替换内容；切换目标、隐藏弹窗或发布新一轮识别内容时重置为折叠。

展开和收起都重新测量尺寸，并沿用现有定位规则。长原文和译文自动换行，超出可用高度时在弹窗内部滚动。展开后鼠标可能正好落在弹窗内，要更新停留判断，避免刚点开就消失。点击、滚轮继续由弹窗接收，不穿透到游戏，也不抢焦点。

### 6. 语言与识别一起更新

整句译文使用请求开始时的有效释义语言，和词义、语法保持一致。按钮、标题和状态仍使用界面语言。

保存新的释义语言时，当前显示内容不立即翻译；下一次实际识别完成后，整句译文与词义一起更新。尚未更新时，展开仍展示当前已发布结果的译文，不把它标成新语言。不会因保存设置额外调用模型。

整句结果和本轮词义在同一次覆盖层更新中发布。新的识别、换目标或停止识别之后，旧任务不能更新译文。窗口暂时隐藏期间，只允许当前有效任务更新保存结果，不自行打开弹窗；恢复后也需要用户重新展开。

### 7. 详情弹窗使用普通样式

按用户对 PhraseOverlay 的明确要求，整个详情弹窗及其整句译文按钮、原文区和译文区都不使用 FluentLight 光效。不增加灯光宿主、表面标记或应用层灯光装饰回调。

继续复用现有弹窗的字体、配色、圆角和深浅主题画刷；按钮可以有普通的悬停、按下和键盘焦点反馈。窗口保持不激活、可接收鼠标的现有行为，也保留没有应用资源时的独立加载能力。其他界面的 FluentLight 要求不在本次例外范围内。

### 8. 设置开关与即时显示

在设置页 AI 设置区域、释义语言附近放置“整句翻译”开关，说明“开启后，分析时生成整句译文，点击弹窗顶部按钮查看”。默认开启，旧配置没有该设置或值无效时也按开启处理，保持原方案的默认体验。用户关闭后，后续分析可以省去整句译文的输出。

通过现有 `ISettingsService` 的 `SentenceTranslationEnabled` 键保存 `true` 或 `false`，不直接访问配置文件。切换后自动保存，不另加保存按钮。保存失败时保留原来的有效值，开关恢复并给出本地化提示，不能显示已经生效。

- **关闭：** 立即收起已展开译文，隐藏当前弹窗和之后弹窗的译文入口，保留词义、读音和语法。之后开始的请求不生成译文。
- **重新开启：** 恢复顶部入口且保持折叠。当前结果已有合法译文时可以直接查看；当前结果来自关闭状态的分析时，点击提示“下次识别时生成整句译文”，不自动补发请求。
- **分析还没结束：** 已发出的请求按开始时的开关正常完成和缓存；入口是否显示始终服从当前设置。关闭后，晚到的译文不能把入口重新打开。
- **下一次识别：** 使用新开关值，即使原文没有变化，也不能被“与上次相同”判断跳过。保存设置本身不启动 OCR 或模型请求，也不改变自动识别的开启状态。

显示开关的变化由设置入口通知覆盖层更新，只调整译文区可见性，保持已有分析内容数据只读。设置页开关沿用现有共享样式及主窗口 FluentLight 宿主；该规则不应用到明确豁免的详情弹窗。

## Risks / Trade-offs

- **输出更多、分析可能更慢** → 使用固定的 20 段短句、跨行长句和多句台词，在相同模型配置下比较增加前后的请求数、耗时中位数和输出量。记录实际差异；本次不承诺零延迟增长，也不直接改成另一套请求方案。
- **缺少前后台词，人物指代仍可能不准确** → 明确标注“AI 参考译文”，同时展示原文；提示词要求不猜人物姓名，首版不扩展历史上下文。
- **重复词语或缓存位置变化造成错配** → 按当前句段关联，并覆盖同词不同句、跨行变化和缓存命中的检查。
- **关闭时的缓存被开启后误用，或旧响应重新显示入口** → 缓存包含请求开关值，显示时再检查当前设置，覆盖分析中切换开关和相同原文重新识别的场景。
- **展开后窗口变大，停留判断失效** → 展开后重测尺寸、更新鼠标停留范围，验证屏幕边缘、滚动和不同缩放比例。
- **另一个快捷键变更也调整隐藏行为** → 本变更只给译文增加同样的保存与隐藏规则，不定义新的隐藏操作；落地时与 `add-reading-keyboard-shortcuts` 保持一致，不覆盖其行为。

## Migration Plan

1. 增加开关的读取与保存，将请求开关值加入分析数据、三种协议和缓存匹配，再把结果传到详情弹窗。
2. 增加设置页开关与顶部折叠区，补齐本地化文案，验证关闭时隐藏和下次识别生效。
3. 旧配置没有 `SentenceTranslationEnabled` 时默认开启，无需改写旧配置；分析缓存仅在内存中，重启后自然使用新结果。
4. 需要回退时撤回相关代码和文案，旧版本可忽略新增的布尔设置键。
