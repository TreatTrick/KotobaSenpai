## Context

应用是 WPF + MVVM，Core 定义接口，Platform.Windows 提供系统实现，DesktopComposition 统一装配。已有 Inno Setup 打包脚本、关闭时停止识别的流程、用户目录中的设置和词典，以及 FluentLight 共享样式。

## Goals / Non-Goals

**Goals:**
- 用户在关于页完成检查、下载、校验、更新和重启。
- UI 不直接联网、写文件或启动安装器，更新不耦合到 OCR 业务。
- 保留现有安装方式和用户数据，不增加第三方依赖。

**Non-Goals:**
- 本次不做增量更新、预览版通道、定时后台下载、断点续传或自定义安装界面。
- 不覆盖源码构建目录，不强制结束进程，不保证跨版本自动回滚。

## Decisions

### 1. 按已有依赖方向拆分

```text
AboutPage（XAML、打开固定网页）
    → AboutPageViewModel（按钮、进度、本地化、取消）
        → Core.Updates（Release 数据、更新来源接口、安装接口）
            ← Platform.Windows.Updates（GitHub、文件校验、Inno Setup）

DesktopSession 监听“安装器已启动”，调用现有正常关闭流程。
DesktopComposition 创建上述对象，不在 ViewModel 内找服务。
```

保留两个外部接口：更新来源负责查询与下载；安装接口负责确认安装位置、再次校验和启动安装器。这两个边界支持替换网络和系统操作进行测试，也符合现有架构。不会增加只有转发作用的工厂、仓储或更新框架。

`Core.Updates` 放在第 1 层，只使用第 0 层的错误码，不引用同层或识别相关能力；分层表和架构测试一起登记这一能力。

### 2. 只更新 GitHub 正式版本

调用公开仓库 `/releases/latest`，使用单独的 HttpClient，不能复用带有模型服务配置的客户端。只解析三段数字版本（允许标签前缀 v），按数字比较。严格匹配 `KotobaSenpai-版本-win-x64-Setup.exe` 及其官方下载地址。更新说明按纯文本显示，不执行远程 HTML。

下载到 `%LocalAppData%/KotobaSenpai/updates`，先写唯一临时文件，检查总大小和 SHA-256 后才移动为安装包。失败或取消删除临时文件。再次安装时重新检查文件，避免把被改动的缓存当成有效安装包。

### 3. 安装器负责等待和安装，App 负责正常退出

Windows 安装接口先验证文件和当前安装登记，再启动安装包，传入父进程 ID、原安装目录和更新标志。使用 `/SILENT /SP- /NORESTART` 保留进度窗口。启动成功后通知 DesktopSession 关闭窗口，沿用停止识别、取消任务和释放锁的既有代码。

Inno Setup 的更新模式等待父进程最多 60 秒；超时则报错，不强杀进程。更新模式安装完成后启动应用，普通安装保留原来的启动复选框。自动重启应用只由一个入口负责。沿用原 AppId，不触碰用户数据目录。

### 4. 版本和 UI 尽量复用

共享构建属性保存默认三段版本。打包脚本无参数时读取此版本，有参数时统一传给发布和安装器。关于页读取应用程序集版本。

页面放到现有导航第三项，复用 SettingsCard、按钮样式、页面间距和主窗口 FluentLightHost。用户文字放中英文 resx；代码、注释、日志、测试使用英文。

## Risks / Trade-offs

- GitHub 访问失败或限流 → 有超时、取消和重试，不影响识别。
- 新版缺少匹配安装资产或摘要 → 明确提示，禁止执行未知文件。
- 下载损坏或缓存被改动 → 下载后和启动前都校验大小与摘要。
- 安装器启动失败 → 留在应用内并显示错误；启动后由安装器显示安装错误。
- 本地开发版本误更新 → 只有安装登记与当前目录一致时才允许自动安装。
- 全量安装包较大 → 显示文件大小和进度，允许取消；以后确有需要再考虑增量更新。

## Migration Plan

首次发布带本功能的版本仍按现有安装包方式安装。之后的新安装包都包含更新模式。未来发布必须保持 Release 标签、资产名称、构建版本一致，并提供 GitHub 资产 SHA-256。失败时用户仍可手动运行官方安装包修复。

## Open Questions

无。按用户选定的现有 Inno Setup、显示进度、安装成功后重启方案实现。
