## Context

当前 `Token` 已保存 UniDic 的原始 `aType`，`UniDicTokenizer` 也能从 `MeCabUniDic22Tagger` 读取它；但 `aType` 只是原始字段，尚未转换为 UI 可以直接使用的音调核位置。`LookupSpan` 会把多个 UniDic token 合并为一个本地词，`GroupedWord` 已通过 `SourceTokens` 保留合并前的 token，但其显示 token 目前只复制第一个 token 的部分元数据。覆盖层只绘制单色振假名，`PhrasePopup` 和词义模型只传递读音。

DokiDokiDict 的实现提供了可复用的行为基线：把 `aType` 解析为 `0` 或第 N 拍下降的位置；把读音拆成拍；用 `L/H` 模式决定振假名颜色；对没有振假名文字的假名/送假名画对应的小点。KotobaSenpai 只复用这个行为和 UniDic 字段语义，不引入 Doki 的 Kanjium 词典、人工覆盖表或其他外部数据源。

## Goals / Non-Goals

**Goals:**

- 保留完整原始 `AType`，同时为每个 token 提供可空的规范化音调核位置。
- 使用出现形读音生成稳定的拍列表、红/蓝高低模式和可读的 `[N] LHL` 文本表示。
- 在合并词、LLM 句段 token 引用、局部词义和短语详情中保留每个源 token 的音调，不因合并而只取第一个 token。
- 在现有覆盖层几何、字号、刷新、悬停和点击穿透行为内增加按拍振假名与假名小点。
- 音调只作为本地展示元数据；provider 请求仍发送现有语义字段，不发送仅用于渲染的格式化音调文本。

**Non-Goals:**

- 不引入 Kanjium、NHK 或其他音调词典，也不添加 DokiDokiDict 的人工修正表。
- 不根据上下文重建跨词的实际音调短语；本次只展示 UniDic 为每个 token 提供的 `aType`。
- 不改变 UniDic 分词边界、JMdict 最长匹配、LLM 释义内容、短语分析并发或 provider wire protocol。
- 不新增用户可配置的音调颜色设置；本次固定使用红色表示高音、蓝色表示低音，避免设置迁移和 UI 复杂度。

## Decisions

### 1. 在 token 上同时保留原始值和规范化值

`Token.AType` 继续保存 UniDic 解码后的原始字符串，包括 `0,2` 这类多值内容。新增的可空规范化字段保存音调核位置：`0` 为平板型，`1` 为头高型，`N` 为第 N 拍后下降。规范化解析放在 Core 的纯逻辑 helper 中，并在 `Token` 构造时由 `AType` 派生，使现有直接构造 `Token` 的测试和调用方不必增加必填参数。

解析规则与 DokiDokiDict 对齐：去除空白，`*`/空值/非数字/负数视为未知；多值只取第一个合法候选；最终拍模式生成时，超出读音拍数的音调位置视为无效。原始字段永远不被覆盖，未来若需要按词性或外部词典改选候选值仍有输入依据。

### 2. 使用共享拍计算器，而不是在 WPF 绘制代码中解析 `aType`

Core 提供拍拆分和模式计算：小假名与前一假名组成一拍，`っ`、`ん`、长音等独立计拍；单拍按高音处理；多拍使用东京式模式：平板 `L H...`、头高 `H L...`、中高/尾高 `L H...H L...`。计算器输出拍文本、每拍的高低布尔值和格式化 notation，WPF 只负责把已计算的拍映射到屏幕坐标。

这样可以在 Core 测试中覆盖音调语义，在 Windows 测试中只验证颜色/位置选择；同时释义弹窗可以复用同一个 notation，不需要复制算法。

### 3. 保留合并词的源 token 音调序列

`LookupSpan.Tokens` 和 `GroupedWord.SourceTokens` 继续作为音调的权威来源。合并词显示 token 可以继续服务于 surface、reading 和词典 lookup，但渲染与词义展示不得使用它的单个 `AType`/音调字段代表整个合并词。新增的本地音调片段按源 token 顺序保存读音、音调核、拍模式和对应的 surface/reading 偏移。

对于 `LocalSpanSummary`、`WordMeaningView` 和 phrase part view，沿用同样的有序片段结构。短语详情没有 LLM 词义时也能从本地词片段生成读音和音调回退；有 LLM 词义时只叠加 provider 返回的 POS、释义和语法。

### 4. 沿用现有覆盖层布局，用比例映射处理当前的词级几何

现有覆盖层持有词的行级 union rect，而不是每个 OCR 字符的独立屏幕 rect。对每个源 token/显示片段，在对应词 rect 内按 surface 字符比例计算横向范围，再按拍数均匀分配颜色文字或小点；跨行词继续逐行绘制，字号、DPI 转换、顶部裁剪和静态点击穿透保持现有实现。

- 含汉字的片段：汉字对应的读音振假名按拍绘制，高音使用红色 `#FF4444`，低音使用蓝色 `#4488FF`，保留现有黑色描边。
- 纯假名或汉字词的送假名：不重复绘制振假名文字，而在每个假名拍的上方按同一模式绘制实心小点。
- `aType` 未知或无效：汉字仍使用现有单色振假名；没有振假名文字的纯假名/送假名不绘制音调点。
- 平板型按 DokiDokiDict 保留尾部辅助标记，用来表示词内没有下降点；它是辅助标记，不改变红/蓝拍颜色。

### 5. 释义展示使用本地音调片段，不扩展 LLM 协议

词弹窗在现有词头、词性、读音、释义和语法中增加音调字段；短语/句子弹窗在每个成员本地词条旁显示读音和音调。展示文本使用统一 formatter（例如 `[2] LH↓L`），未知时显示本地化的“音调未知”或省略音调字段，但不得隐藏读音或释义。

`PhrasePromptBuilder`、provider parser 和 provider schema 不增加 pitch 字段：LLM 仍只引用已有 token ID/本地 span，音调由本地 token 在分析结果映射后补回。这样不会要求模型重复或猜测 UniDic 数据，也保持不同 provider 协议的语义一致。

## Risks / Trade-offs

- [UniDic 的多值 `aType` 可能对应不同读法或词性] -> 固定选择第一个可解析候选，同时保留原始多值字符串；本次不宣称它等同于人工校订音调。
- [合并词只有 union rect，无法精确复现每个 OCR 字符的宽度] -> 使用现有词级几何和比例映射，优先保持跨行/DPI 稳定；增加纯逻辑拍范围测试，避免新增像素级脆弱依赖。
- [短语/词义数据链路新增片段字段会触及多个 record 构造器] -> 片段字段使用空集合或 nullable 的兼容默认值，先更新 Core 工厂和 validator，再统一更新测试替身。
- [音调未知时红蓝标记缺失可能被误认为低音] -> 未知状态明确禁止绘制音调颜色/小点，并在弹窗使用本地化未知提示或保留无音调字段。
- [当前 `FuriganaFontScale` 历史规格与实现默认值可能存在差异] -> 本 change 不调整字号默认值，只复用现有解析和布局路径，避免把无关视觉变更混入音调功能。

## Migration Plan

这是本地模型和 UI 的向后兼容扩展，不需要持久化数据迁移或 provider 版本迁移。实施时先加入 Core 音调模型/计算器并更新 tokenizer 与传播链，再更新 WPF 绘制和 popup；发布前运行现有全量测试及新增音调测试。回滚时删除音调绘制和新增字段消费即可，原始 `AType`、读音、下划线和释义流程仍可独立运行。

## Open Questions

- 本次不开放颜色设置；若后续需要用户自定义，应另建设置变更并处理本地化、默认值和迁移。
- 目前按 UniDic 第一候选解释多值 `aType`；若产品需要上下文选择或 Kanjium 修正，应另建独立的数据源与优先级规格。
