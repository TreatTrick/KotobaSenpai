## Why

当前覆盖层将“目标窗口必须是前台窗口”当作可渲染条件，导致 Aokana 仍可见且未被遮挡时，KotobaSenpai 自身获得焦点也会错误隐藏已有识别结果。覆盖层还没有明确的目标窗口所有权与会话生命周期规则，窗口隐藏、恢复、移动、缩放和销毁时容易出现残留、失步或不必要的重新识别。

## What Changes

- 将渲染窗口改为 Aokana 的 Win32 owned top-level window，并关闭全局置顶行为，使其跟随目标窗口的层级关系。
- 将“目标可渲染”与“目标处于前台”解耦；目标可见且未被遮挡时，即使 KotobaSenpai 获得焦点，也恢复或保持当前覆盖层。
- 保留目标窗口的可见性、最小化、有效句柄和遮挡校验，用于控制覆盖层显示以及拒绝屏幕 OCR 捕获。
- 将任意正面积的其他窗口重叠视为遮挡，并将 KotobaSenpai 主窗口纳入遮挡判断；只排除覆盖层自身相关窗口。
- 目标窗口临时隐藏、最小化或被遮挡时立即隐藏覆盖层并停止悬浮交互，但保留当前识别会话；恢复后只重新定位并恢复已有词线、假名和短语标记，不自动 OCR。
- 目标窗口移动、大小变化或 DPI 变化时，基于识别时保存的归一化几何实时重投影覆盖层，不重复缩放已有屏幕坐标，也不触发自动 OCR。
- 目标窗口销毁或切换时清理当前识别会话和覆盖层状态，并允许重新选择目标窗口。
- 补充目标窗口显式显示/隐藏事件的跟踪与诊断，使覆盖层生命周期与目标状态保持一致。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `target-window-tracking`: 扩展目标窗口的 owned overlay 生命周期、可见性/遮挡事件和归一化几何跟踪规则。
- `window-word-overlay`: 调整覆盖层的渲染条件、遮挡行为、会话保留/清理以及恢复和重定位行为。

## Impact

- 影响 `WinEventTargetWindowTracker`、`TargetWindowSnapshot`、`WpfOverlayRenderer` 以及识别工作流对目标状态的校验和会话清理逻辑。
- 需要调整 Win32 窗口 owner、窗口层级和目标窗口事件订阅，不引入新的外部依赖或持久化数据格式。
- 需要补充 Core 与 Windows 平台测试，覆盖目标状态转换、遮挡判断、owned window 生命周期、重定位和“不自动 OCR”约束。
