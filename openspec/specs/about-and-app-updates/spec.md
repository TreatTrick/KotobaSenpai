# 关于页与应用更新

## Purpose

定义关于页的应用信息、GitHub 正式版检查、安装包下载校验，以及通过现有安装器升级并重启的行为，同时保留用户数据和现有架构边界。

## Requirements

### Requirement: 关于页显示应用信息

应用必须（MUST）在左侧导航提供“关于”页，显示图标、简介、当前应用版本、官网、GitHub 和问题反馈入口。版本必须来自应用本身，不能把 .NET 运行时版本当成应用版本。

#### Scenario: 打开关于页
- **WHEN** 用户点击“关于”
- **THEN** 页面显示应用信息和软件更新区域，且不重新初始化 OCR、词典或模型。

#### Scenario: 页面适配界面设置
- **WHEN** 用户切换中英文或明暗主题
- **THEN** 关于页文字和状态随设置变化，卡片与按钮使用共享 FluentLight 样式、匹配圆角，并处于主窗口现有的 FluentLightHost 内。

### Requirement: 自动检查最新正式版

应用必须（MUST）在本次运行首次打开关于页时自动查询 TreatTrick/KotobaSenpai 的 GitHub 最新正式 Release，并提供手动重新检查按钮。检查不得阻塞界面，也不得自动下载或安装。

#### Scenario: 发现新版
- **WHEN** GitHub 返回的正式版本大于当前版本，且有对应的 win-x64 安装包和 SHA-256
- **THEN** 显示新版版本号、更新说明、安装包大小和“下载更新”。版本按数字比较，例如 1.10.0 大于 1.9.0。

#### Scenario: 已是最新版
- **WHEN** 最新正式版本不大于当前版本
- **THEN** 显示“已是最新版”，不显示可用的下载或安装按钮，也不降级。

#### Scenario: 检查无法完成
- **WHEN** 网络超时、GitHub 限流、没有 Release，或者新版缺少安装包或有效校验值
- **THEN** 显示明确的本地化提示，允许重新检查，不把失败显示成“已是最新版”，不影响识别功能。

### Requirement: 用户决定下载并可取消

应用必须（MUST）只在用户点击后下载安装包，显示已下载大小和总大小，并允许取消。检查、下载和安装不得重复并发执行。

#### Scenario: 下载成功
- **WHEN** 安装包全部下载且大小、SHA-256 都与选中 Release 的信息一致
- **THEN** 显示“已准备好更新”和“更新并重启”，下载的文件位于用户缓存目录。

#### Scenario: 取消或下载失败
- **WHEN** 用户取消、关闭应用、网络中断、磁盘写入失败，或者校验不一致
- **THEN** 不允许安装，不留下可执行的半成品，并可再次下载。取消不能显示成意外错误。

#### Scenario: 下载来源固定
- **WHEN** GitHub 响应包含安装资产
- **THEN** 只接受官方仓库该版本下的 Windows x64 安装包，通过 HTTPS 下载；不得执行来源不明或没有校验依据的文件。

### Requirement: 点击更新后安装并重启

应用必须（MUST）只在用户点击“更新并重启”后安装，并在启动安装器前再次校验下载文件。应用必须正常停止识别、释放文件和设置锁；安装器必须等待旧进程退出后再替换文件，显示安装进度，成功后启动新版，不自动重启 Windows。

#### Scenario: 正常更新
- **WHEN** 已通过校验的安装包被用户选中安装
- **THEN** 启动现有 Inno Setup 的更新模式，应用正常退出，安装器在原安装目录完成升级并启动应用一次。

#### Scenario: 安装器启动失败
- **WHEN** 文件丢失、文件被改动或者安装器无法启动
- **THEN** 应用保留运行并显示可重试提示，不在安装器尚未启动时退出。

#### Scenario: 旧进程没有退出
- **WHEN** 安装器在限定等待时间内仍无法确认旧进程退出
- **THEN** 停止更新并显示错误，不强制终止旧进程，不替换正在使用的文件。

#### Scenario: 从源码运行
- **WHEN** 应用不是从 Inno Setup 登记的当前安装目录运行
- **THEN** 可以查看和下载新版，但不能自动覆盖开发目录；页面说明需要打开 Release 页面进行手动安装。

### Requirement: 更新保留用户数据

升级必须（MUST）沿用已有的安装标识和目录，保留用户设置、API 配置、语言、主题、快捷键和已安装词典。普通首次安装仍提供原有安装向导。

#### Scenario: 安装新版后重新打开
- **WHEN** 用户完成升级
- **THEN** 应用继续读取原来的用户数据，不能因为升级再次要求用户配置 API 或重装相同词典。

### Requirement: 应用和安装包版本一致

应用构建、安装包名称和安装器显示的版本必须（MUST）使用同一版本来源。发布时 Release 标签必须与该版本一致。版本采用三段数字，例如 1.0.2。

#### Scenario: 默认打包
- **WHEN** 没有传入版本参数而执行打包脚本
- **THEN** 从共享构建属性读取版本，不用当天日期冒充应用版本。

#### Scenario: 指定发布版本
- **WHEN** 使用版本参数构建安装包
- **THEN** 同一版本传给应用构建和 Inno Setup，应用内显示的版本与安装包一致。

### Requirement: 更新逻辑遵守现有架构

实现必须（MUST）保持 Core 无 HTTP、文件系统和 WPF 依赖；ViewModel 只依赖 Core 接口和数据，不依赖 Windows 实现或服务容器。依赖必须在 DesktopComposition 中装配。

#### Scenario: 验证更新能力
- **WHEN** 运行更新行为测试和架构测试
- **THEN** 能在不访问真实 GitHub、不启动真实安装器的情况下验证版本判断、下载失败、取消和安装交接；既有依赖方向测试继续通过。
