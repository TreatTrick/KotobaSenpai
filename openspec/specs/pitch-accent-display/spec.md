# pitch-accent-display Specification

## Purpose
定义 UniDic 音调信息从分词结果到本地振假名、假名音调标记、词语释义和短语详情的保存、传播与展示契约。

## Requirements

### Requirement: 规范化并保留 UniDic 音调
系统 SHALL 在每个 UniDic token 上同时保留原始 `aType` 字符串和可空的规范化音调核位置。规范化位置 SHALL 使用 `0` 表示平板型、`1` 表示头高型、`N` 表示第 N 拍后下降；空值、`*`、负数、非数字或无法验证的值 SHALL 表示音调未知。多值 `aType` SHALL 选择第一个可解析候选，但不得丢弃原始多值字符串。

#### Scenario: 保留单值音调
- **WHEN** UniDic token 的 `aType` 为 `2`
- **THEN** token 保留原始字符串 `2`，并提供规范化音调核位置 `2`

#### Scenario: 处理多值音调
- **WHEN** UniDic token 的 `aType` 为 `0,2` 或等价的带引号 CSV 值
- **THEN** token 保留完整解码后的原始值，并使用第一个可解析候选 `0` 作为本地展示位置

#### Scenario: 未知音调不伪造结果
- **WHEN** UniDic token 的 `aType` 为空、为 `*` 或不是合法数字
- **THEN** token 的规范化音调为未知，后续 UI 不得把它当作低音或平板型绘制

### Requirement: 按读音拍计算高低模式
系统 SHALL 根据 token 的出现形读音拆分拍，并根据规范化音调核生成与拍一一对应的高/低模式。小假名 SHALL 与前一个假名组成一拍；`っ`、`ん` 和长音 SHALL 各自计为一拍。计算结果 SHALL 提供统一的可读 notation，例如 `[2] LH↓L`，供覆盖层和释义详情复用。

#### Scenario: 计算平板型
- **WHEN** 一个三拍读音的音调核为 `0`
- **THEN** 高低模式为 `L H H`，且 notation 标明音调核为 `0` 而不插入词内下降箭头

#### Scenario: 计算头高型
- **WHEN** 一个三拍读音的音调核为 `1`
- **THEN** 高低模式为 `H L L`

#### Scenario: 计算中高或尾高型
- **WHEN** 一个四拍读音的音调核为 `2` 或 `4`
- **THEN** `2` 生成 `L H L L`，`4` 生成 `L H H H`，并在 notation 中保留下降位置/尾高标记

#### Scenario: 合并小假名为一拍
- **WHEN** 读音为 `きょう`
- **THEN** 拍序列为 `きょ`、`う`，而不是四个独立字符

#### Scenario: 音调核超出拍数
- **WHEN** 规范化音调核大于读音的拍数
- **THEN** 该 token 的音调模式被标记为未知，系统不绘制错误的红蓝标记

### Requirement: 在本地传播有序音调片段
系统 SHALL 在 `GroupedWord` 保留按源 UniDic token 顺序排列的音调片段与已解析的整词音调（`SpanPitch`）。`WordOverlaySession` SHALL 从 `GroupedWord` 将 `SpanPitch` 与 `WordPitch` 汇入本地 `WordMeaningView`。句段 token 引用和本地合并词摘要 MUST NOT 携带 `SpanPitch`。未发生读音覆盖且未解析出 `SpanPitch` 时，合并词的显示 token 不得覆盖或替代源 token 的音调序列。当词块解析出有效的 `SpanPitch` 时，展示层 SHALL 优先采用 `SpanPitch` 作为该词块的整体音调。当词块的最终有效读音被 JMdict 词典回流、助数词推导或 LLM 语境纠偏覆盖、且未能解析出有效的整词 `SpanPitch` 时，系统 MUST 将该词块对应的源 token 展示音调片段置为空（视为整组音调未知），不得把 UniDic 原同形异音词的过期音调核套用到新读音上。所有音调数据 SHALL 只用于本地渲染、详情展示和本地诊断，不得自动加入 LLM provider payload。

#### Scenario: 合并词未命中整词音调时保留每个源 token 的音调
- **WHEN** 一个本地合并词由两个 UniDic token 组成、未触发读音覆盖、未命中整词 `SpanPitch`，且两个 token 的 `aType` 不同
- **THEN** 合并词仍能按源 token 顺序取得两份音调片段，渲染和详情不会只使用第一个 token

#### Scenario: 读音被覆盖后若命中整词音调则传播整词音调
- **WHEN** `一週間` 的有效读音由 JMdict 覆盖为 `いっしゅうかん`，且整词分层解析命中 `SpanPitch([3])`
- **THEN** `GroupedWord` 与 `WordMeaningView` 传播该整词 `SpanPitch`，覆盖层与弹窗均按整词 `[3]` 展示

#### Scenario: 读音被覆盖且未命中整词音调时抑制过期音调
- **WHEN** `頭を垂れる` 的有效读音由 JMdict 从 `あたまをたれる` 覆盖为 `こうべをたれる`，且整词分层解析未命中整词 `SpanPitch`
- **THEN** 该词不保留过期的 `PitchAccents` 片段，绝不套用原 `あたま[2]` 的高低音着色、圆点或数字标记

#### Scenario: 整词音调经会话汇入释义视图
- **WHEN** 一个句段被构建为 LLM 分析请求
- **THEN** `SpanPitch` 仅沿本地会话路径进入 `WordMeaningView`。未覆盖词的源 token 音调仍可用于本地展示，provider 请求体保持既有语义字段

#### Scenario: 缺少音调时保留其他本地数据
- **WHEN** 某个 token 没有有效 `aType` 且词块未命中整词 `SpanPitch`，或因读音覆盖且无整词命中导致音调未知
- **THEN** surface、有效 reading、POS、词义和几何仍然可用，仅缺少有效音调的部分表现为未知

### Requirement: 读音纠偏后回查 UniDic 单词音调与分句覆盖层上色
对于 JMdict 或 LLM 纠偏后的有效读音，系统 SHALL 先执行整词优先的分层离线音调解析；仅当未能解析出整词 `SpanPitch` 时，如果读音变化可以唯一对齐到一个源词元，系统 SHALL 使用该词元的原表记、新读音、词性和活用信息匹配 UniDic 词条并记录为单 token 单词参考（`WordPitch`），同时生成按独立词/未改写活用段划分的 `CorrectedPitchAccents`（纠偏词元使用新读音首候选核位，其余未改写词元保留各自 UniDic 原调或形态学活用音调）。覆盖层 SHALL 使用 `CorrectedPitchAccents` 按各子段分别绘制红蓝高低音与圆点，不得把单 token 单词参考冒充整组 `SpanPitch` 涂满整条短语；悬停弹窗和短语成员词表 SHALL 继续将此类结果标为 UniDic 单词音调并保留全部有效候选；当无法唯一对齐或查不到有效音调时，系统 SHALL 保持音调未知并在覆盖层回退为普通单色振假名。

#### Scenario: 整词未命中时覆盖层按子词分句上色且弹窗显示单词音调参考
- **WHEN** `頭を垂れる` 的有效读音为 `こうべをたれる`，整词分层解析未命中整词音调，且 UniDic 命中 `頭（こうべ）` 候选音调 `0,3`、未改写动词 `垂れる` 音调为 `2`
- **THEN** 覆盖层分别按 `頭（こうべ）[0]` 与 `垂れる（たれる）[2]` 绘制红蓝高低音与圆点（绝不套用旧 `あたま[2]`），弹窗显示标有 UniDic 来源的 `頭（こうべ）` 单词音调及两个候选

#### Scenario: 活用惯用句的未改写动词段按形态学规则计算分句音调
- **WHEN** `頭を垂れた`（`こうべをたれた`）或 `踵を返して`（`きびすをかえして`）未命中整词音调且纠偏词元唯一对齐到 `頭` / `踵`
- **THEN** `CorrectedPitchAccents` 将纠偏名词按新读音首候选上色，并将未改写的活用动词段（`垂れ+た` → `[1]`、`返し+て` → `[1]`）按形态学规则计算音调

#### Scenario: 对齐不明确或查不到新读音音调时回退为单色振假名
- **WHEN** 纠偏读音未命中整词音调、且无法唯一分配给一个原词元或 UniDic 未返回有效匹配的音调
- **THEN** `CorrectedPitchAccents` 为空，覆盖层显示单色振假名，弹窗显示音调未知并保留纠偏后的有效读音

### Requirement: 整词优先的分层离线音调解析
系统 SHALL 在确定每个词块的最终有效读音后（包括首次本地分组以及 LLM 返回经校验的语境读音纠偏之后），按以下优先级在本地离线解析该词块的整词音调（`SpanPitch`）：
1. 项目人工校正表，优先按 `(原始表记, 平假名有效读音)` 精确匹配，未命中时再尝试适用的汉数字规范化表记；
2. 离线 Kanjium SQLite 词典（`pitch-accent.db`），按 `(表记, 平假名有效读音)` 精确匹配（含对阿拉伯数字表记的汉数字规范化查表）；
3. 高确定性白名单助数词规则（`週間`、`時間`、`年生`、`ヶ月` 变体、`曜日`）；
4. 基于 UniDic `AType`/`AModType`/`AConType` 的形态学音调结合规则（仅在未发生读音覆盖时适用）。

整词词典查询 MUST 仅使用词块的出现形 `Surface` 与最终有效读音，不得将 `LookupKey` 辞书形的词典音调直接套用到活用出现形（例如不得将 `食べる[2]` 套用到 `食べて`）；活用出现形应由第 4 层形态学规则按 UniDic 结合与变形字段推导出实际音调（如 `食べて` → `[1]`）。整词解析命中的全部合法候选核位置 SHALL 按来源顺序保留在 `SpanPitch.Positions` 中，并以第一个候选作为主展示位置；解析结果 SHALL 仅用于本地展示与诊断，不得加入 LLM 请求体。

#### Scenario: 一週間经离线词典解析出整词音调
- **WHEN** `一週間`（或 `1週間`）经有效读音解析确定为 `いっしゅうかん`
- **THEN** 分层解析通过 Kanjium 精确命中整词 `SpanPitch`，位置为 `[3]`，来源为 `Dictionary`

#### Scenario: 三週間经白名单助数词规则解析出整词音调
- **WHEN** `三週間` 经词块分组确定有效读音为 `さんしゅうかん`，且人工校正表与离线词典均无整词记录
- **THEN** 分层解析回退至白名单助数词规则，产出整词 `SpanPitch`，位置为 `[3]`，来源为 `CounterRule`

#### Scenario: LLM 纠偏读音后重新解析整词音调
- **WHEN** `額` 的有效读音被 LLM 从 `がく` 纠偏为 `ひたい`，且离线词典收录 `額（ひたい）` 的整词音调
- **THEN** 系统以 `("額", "ひたい")` 重新运行分层解析并更新为新读音对应的整词 `SpanPitch`，不再停留在音调未知或仅单 token 参考

#### Scenario: 活用形不误用辞书形词典音调而由形态学规则解析
- **WHEN** 词块 `Surface` 为 `食べて`、`LookupKey` 为 `食べる`、有效读音为 `たべて`，离线词典仅收录 `食べる` 而未收录 `食べて`
- **THEN** 整词词典查询不以 `食べる` 查表，第 4 层形态学规则基于 `食べ(aType=2, aModType=M4@1)` 与 `て(aConType=動詞%F1)` 产出 `SpanPitch([1], MorphologicalRule)`；当形态学字段缺失时安全回退为空

### Requirement: 基于 UniDic 结合与变形字段计算形态学整词音调
对于未发生读音覆盖（`HasOverriddenReading == false`）且在人工校正表、离线词典和白名单助数词规则均未命中的词块，系统 SHALL 使用 `SourceTokens` 的 UniDic `AType`、`AModType` 与 `AConType` 在本地离线计算整词音调核（来源标记为 `SpanPitchSource.MorphologicalRule`）：
- 单 token 词块仅在携带可解析的 `AModType`（`M1@k`、`M2@k`、`M4@k`）且具备有效基础音调核时应用变形计算；无 `AModType` 的普通单 token SHALL 返回未知（沿用既有单 token `aType` 展示）。
- 多 token 词块 SHALL 从左至右逐语素递推计算：按 `AModType`（含 `M4@k` 对无声化母音不前移与特殊拍 `っ`/`ん`/`ー` 继续左移一拍的保护）处理活用变形，按 `AConType` 处理付属語（`F1`–`F6`，含 `助動詞-タ` 单拍末拍平板归一避免产生动词尾高型）、接尾辞/複合語（`C1`–`C5`）与确定性接頭辞（`P1`/`P2`/`P6`/`P13`/`P14`）的结合变调，并允许活用助动词多层连续叠链。
- 当词块发生读音覆盖、任意必需 token 缺少有效读音/基础音调/匹配规则，或遇到未支持的规则标记或越界结果时，系统 MUST 失败关闭并返回未知，交由既有回退路径处理，不得伪造音调。

#### Scenario: 单 token 意志形应用 M1 变形规则
- **WHEN** `食べよう`（`aType=2, aModType=M1@1`）与 `行こう`（`aType=0, aModType=M1@1`）未在离线词典命中
- **THEN** 形态学规则分别计算出 `SpanPitch([3], MorphologicalRule)`（`たべよ＼う`）与 `SpanPitch([2], MorphologicalRule)`（`いこ＼う`）

#### Scenario: 一段与五段动词て形及过去形正确变调
- **WHEN** 未发生读音覆盖的多 token 活用词块 `食べて`、`食べた`、`見て`、`集めて`、`書いて`、`歩いて`、`飲んで`、`呼んで`、`行った`、`呼んだ` 进入解析
- **THEN** 形态学规则分别计算出 `[1]`、`[1]`、`[1]`、`[2]`、`[1]`、`[2]`、`[1]`、`[0]`、`[0]`、`[0]`

#### Scenario: M4 核前移遵守无声化母音与特殊拍保护
- **WHEN** `つけて`（`つ` 无声化）、`助けて`（`す` 无声化）与 `ぞんじて`（核前移落于 `ん`）进入解析
- **THEN** 形态学规则分别计算出 `[2]`（`つけ＼て`）、`[3]`（`たすけ＼て`）与 `[1]`（`ぞ＼んじて`）

#### Scenario: 动词多层助动词叠链连续递推准确
- **WHEN** `食べます`、`行きます`、`食べません`、`食べませんでした`、`食べない`、`行かない`、`食べなかった`、`行かなかった`、`食べたい`、`食べられる`、`食べさせられる`、`食べさせられた`、`行ったら`、`食べたら` 进入解析
- **THEN** 形态学规则分别计算出 `[3]`、`[3]`、`[4]`、`[4]`、`[2]`、`[0]`、`[2]`、`[3]`、`[3]`、`[4]`、`[6]`、`[5]`、`[3]`、`[1]`

#### Scenario: い形容词活用链正确计算整词音调
- **WHEN** `高かった`、`赤かった`、`面白かった`、`高くて`、`赤くて`、`高いです`、`赤いです` 进入解析
- **THEN** 形态学规则分别计算出 `[2]`、`[2]`、`[4]`、`[2]`、`[2]`、`[2]`、`[2]`

#### Scenario: 词典缺项的能产前后缀复合词按 C/P 规则计算
- **WHEN** 离线词典未收录 `論理的`（`C4`）、`物理学`（`C3`）、`食べやすい`（`C1`）、`食べすぎる`（`C1`）或 `食べすぎた`（`C1` + `F2@1`）
- **THEN** 形态学规则分别计算出 `[0]`、`[3]`、`[4]`、`[4]`、`[3]`

#### Scenario: 读音被覆盖或规则不完整时失败关闭
- **WHEN** 词块 `HasOverriddenReading` 为 `true`，或某个源 token 缺少必需 `AType`/`AConType` 或包含未支持的规则标记
- **THEN** 形态学规则返回空结果，不伪造整词 `SpanPitch`
